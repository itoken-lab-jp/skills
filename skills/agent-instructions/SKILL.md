# エージェントへの指示を置く・保つ

指示ファイルは、エージェントが毎回（または決まった場面で）読み込む文。読ませる量が増えるほど、1行ごとの効き目は下がり、古くなる所も増える。置くとき・足すとき・見直すときのどれも、次の3つで決める。

- **毎回読ませるのは、コードを読んでも分からないことだけ。** 1行ごとに「これを消したら、エージェントは間違えるか」で残すかを決める。
- **正本は1つ。** 同じ決まりを2か所に書くと、片方だけが直ってずれる。ほかの場所からは正本を指す。
- **書いてあることは実物と照らす。** コマンド・パス・関数名・仕組みについての主張は、書いた日から古くなる。

各ツールが何をどこから読むか（ファイル名、置き場所、上限の大きさ、取り込みの書き方）は、ツールと版で違い、よく変わる。書く前に、使うツールの公式の docs で確かめる。下の数字は確かめた日つきの目安。

## 1. 新しいリポジトリに置く

1. **先に決める**：触るツール（どれとどれか）、走らせる所（手元か、クラウドか）、公開か非公開か（指示ファイルも公開される）、エージェントの設定に詳しくない人も使うか。
2. **原本を1本作る**：複数のツールが読むファイル（`AGENTS.md` は Codex・Cursor・Antigravity などが読む。読まない道具、設定で読ませる道具もあるので、使う道具の docs で確かめる）を原本にし、ほかのツール専用のファイルは原本を取り込むか指すだけにする（例：Claude Code の `CLAUDE.md` は `@AGENTS.md` の1行）。書くのは次だけ。
   - 何のリポジトリか（1〜2行）と、正本の場所（docs・Issue・設計の記録）
   - build・test・lint のコマンドのうち、推測できないもの（絞り込みの印、前提の道具）
   - 既定と違う決まり、そのリポジトリ特有の落とし穴
   - 公開の境界と、戻せない操作（本番・課金・外への送信・秘密のデータ）の扱い
3. **書かない**：コードから分かること、言語の一般的な作法、ファイルごとの説明、README の丸写し、すぐ変わる情報、長い経緯（経緯は docs に置いてパスで指す）。
4. **機械の守りを1つ用意する**：エージェントが「完了」の前に走らせる検査（速いテスト・lint・型・ビルドのどれか）のコマンドを原本に書く。main の守り（必須の CI、直接の push を止める設定）は、人に頼む項目として挙げるか、権限があれば作る（作り方と、必須の CI の落とし穴は [references/main-protection.md](references/main-protection.md)）。守りたいことは注意書きより設定・CI・フックで止める。
5. **最初は小さく**：Skill・サブエージェント・フック・パスで絞ったルールは、先回りして作らない。「6. 確かめる」をして終える。

## 2. 足す

- **足す目安**：同じ説明を2回したとき、同じ失敗が2回起きたとき。足す前に、既にある所を直して済まないかを見る。
- **置き場を選ぶ**：どの作業でも要ることは原本に。一部のフォルダーにだけ効く決まりは、そのフォルダーの指示ファイルかパスで絞ったルールに。毎回は要らない手順や知識は Skill に。毎回必ず起きてほしいこと（編集後の整形、危ない操作を止める）はフックや CI に。
- **事故から生まれた決まりは、理由と一緒に書く**（何が起きたか1文）。理由の無い決まりは、次に見直す人が消してしまう。
- 個人の事情（手元の URL、好み）は、共有の指示ファイルに書かず、ツールの個人用の置き場に書く。
- 全体の設定（ホームの指示ファイル）を持たないほかの人も使うリポジトリでは、その人たちのエージェントでも同じでないと困ること（共有のものを守る線、チームの手順）を、全体の設定と重なってもリポジトリに書く。

## 3. 見直す

見直す合図：長くなった、守られていないと感じる、使うモデルの世代が変わった、ツールを足した、数か月たった。

1. **測る**：ツールごとに、毎回読み込まれるもの（全体とリポジトリの指示ファイル、取り込んだ文書、常に入るルール、メモリの索引、Skill とサブエージェントの名前と説明）を挙げ、大きさを `wc -c`・`wc -l` で数える。ホームや作業フォルダーのように、リポジトリより上のフォルダーに置いた指示ファイルも数える（そこで起動したセッションに読まれる）。目安（2026-11 時点）：Claude Code は1ファイル 200 行未満、Codex は合計 32KiB を超えた分を読まない、Antigravity は1ファイル 24,000 バイトを超えると切り詰める。直したあとにもう一度測り、どれだけ減ったかを報告に書く。
2. **実物と照らす**：書いてあるコマンドは package.json・Makefile などのスクリプトと、パスと関数名は `ls`・検索と、仕組みについての主張（「〜は読まない」「〜は自動で走る」）は公式の docs と照らす。無いもの・違うものを直す。
3. **重複と食い違いを片づける**：同じ決まりが複数のファイル（ツールごとの指示ファイル、ルールのフォルダー、エディタの設定）に無いかを見る。正本を1つに決め、ほかは指すだけにする。値が食い違っていたら（インデントの幅、テストの置き場）、実物（設定ファイル、今のコード）に合う方へそろえ、どちらとも決められなければ人に聞く。ツールの取り込み機能が作った写しも探す。
4. **古いモデル向けの書き方を外す**：使うモデルの公式のプロンプトのガイドを読み、前のモデルの弱さを補うための書き方を探す。大文字と感嘆符での強調（IMPORTANT・ALWAYS・NEVER）、一般的な「必ず再確認しろ」「毎回すべて読み直せ」、「考えずに答えろ」、特定の古いモデルの不具合を理由にした決まり。今のモデルでは効かないか、過剰に効いて足を引っぱる。
5. **残すものを見分ける**：事故から生まれた領域の知識（本番に流す前の手順、実機での確認、秘密の扱い）は、一般的な再確認とは違うので残す。迷ったら消さずに人に聞く。
6. **外に出す**：経緯、実測値、ファイルごとの説明、言語の一般的な作法は、指示ファイルから外す（docs へ移すか消す）。本文は「何をする・しない」と理由1文と、詳しい正本へのパスにする。
7. **範囲を守る**：見直しで直すのは指示ファイルだけ。コードやテストのおかしな所に気づいたら、直さずに報告に書く。
8. 「6. 確かめる」をする。

## 4. メモリと、PC ごとの設定

- エージェントが自分で書き残したメモリは、全体の指示や実物と食い違えば、そちらを正としてメモリを直す。
- リポジトリの外にある PC ごとの設定（ホームの指示ファイル、有効なままのプラグインや MCP、個人用のルール）は、リポジトリの指示を黙って上書きしていることがある。見直しの対象に入れる。git の外で控えが無いことが多いので、直す案・止める案を人に見せ、決めてもらってから直す。
- 有効な道具（MCP を含む）が数十を超えると、選び方が鈍る。使わないものを止める案を出す。

## 5. 報告する

何を変えたか（ファイルごと）、なぜか（実物と照らした結果）、減った量（前後の大きさ）、残したものと理由、人に決めてほしいこと（食い違いでどちらを正とするか、消してよいか迷ったもの）、確かめたことと確かめていないことを分けて書く。

## 6. 確かめる

- 新しいセッションを開き、指示ファイルが読み込まれたかを見る。ツールに読み込み中の指示を見せるコマンドがあれば使い（2026-11 時点で、Claude Code は `/context`・`/memory`、Codex は `/status`）、無ければ、指示ファイルにしか書いていないこと（テストのコマンドなど）を聞いて答えられるかを見る。今のセッションは、起動したときの内容のまま動いていることが多い。
- 足したフックやガードは、わざと引っかかる操作をして止まるのを見る。
- 自分で新しいセッションを開けないときは、確かめ方を人に渡し、確かめていないと報告に書く。

## 例

頼み：「AGENTS.md と GEMINI.md と .github/copilot-instructions.md があって、どれが効いてるのか分からない。整えて」

1. 3つを読み、大きさを数える。どのツールがどれを読むかを公式の docs で確かめる。
2. 書いてあるビルドのコマンドを Makefile と、パスを `ls` と照らし、無いものを見つける。3つの間で「コミットの書き方」が食い違うのを見つけ、最近の git log に合う方を候補にする。
3. AGENTS.md を正本にして、ほかの2つは正本を指すだけにする（ツールが AGENTS.md を直接読むなら消す）。大文字の強調と経緯を外し、リリースの前の手順（事故の理由つき）は残す。
4. 測り直して前後の大きさを示し、食い違いをどちらに寄せたか（人に決めてほしい点）と、新しいセッションでの確かめ方を報告する。
