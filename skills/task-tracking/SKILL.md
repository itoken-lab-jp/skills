# やることを1つのファイルで管理する

次のセッションは、前の会話を持たない（文脈の要約、別の日、別の PC、別のツール）。AI は、目の前の1件は終わらせるし、すでにある一覧の印も更新する。外すのは、一覧がまだ無い所で、次の形が多い。

- 会話の中で出た「今週中に」「後ででいい」の依頼を、返事の中で「残りは次回」と並べるだけで、どこにも書かない。次の日のセッションには何も残らず、期限のある依頼と、人の返事を待っていた依頼が消える。
- 一覧にしても、何ができたら終わりかを書かない。済みにしたものが本当に済んだかを、あとから誰も確認できない。
- 項目ごとに長いメモ・日程表・優先度の段を追加し、8件で数十行のファイルにする。読み返されなくなる。

この Skill は、残りを会話の外の1つのファイルに置き、次に開いた人や AI がそのまま続けられる形に保つことを受け持つ。

## どこに書くか

1. リポジトリやフォルダーに定め（指示ファイル、README）があれば、それに従う。
2. 票の道具（GitHub の Issue、Linear、Redmine など）を使っている所では、そこに書く。このファイルを別に作って、二重にしない。
3. どちらも無ければ、直下の `TODO.md` 1つに書く。すでに同じ役目のファイル（やることの一覧、進み具合のメモ）があれば、それを使う。

会話、エージェントのメモリだけに置かない。メモリは、ほかのツールとほかの PC から読めない。

## いつ書くか

- 会話の中で出て、その日にやらない依頼（「今週中に」「後ででいい」「〜さんの返事が来たら」）は、出たその場で追加する。止めるときにまとめて書こうとすると、落とす。
- 1件を終えたとき、「今日はここまで」と言われて止めるときに、印と途中の状態を更新する。
- 1つのセッションで終わる1件だけの依頼では、一覧を新しく作らない。そのまま済ませて報告する。すでに一覧があって、依頼された1件がそこに載っていれば、その1件だけをやり、終えたら印を更新して短く報告する。一覧の形や「終わり」の文は書き換えず、依頼されていないファイルに説明を追加せず、次の項目に進む話も追加しない。

## 形

```
# やること

印：[ ] まだ ／ [~] 途中・待ち ／ [x] 済み

1. [x] 夜勤の翌日に早番を入れたら警告を出す
   - 終わり：validate が違反を返す試験が通る。README の「決まり」の表に1行足す。
2. [~] 休業日にシフトが入っていたら警告を出す
   - 終わり：実物の休業日の CSV で check を走らせて、違反が出るのを見る。
   - 途中：判定と試験は済み。CSV は総務の佐藤さんが 11/20 に送る。届いたら列の並びを見て読み込みを足す。
3. [ ] 月間の集計（店舗ごとの合計時間）を出す ― 11/25 の会議で見せる
   - 終わり：`summary` のコマンドで店舗ごとの合計が出る。
```

- **1行に1件、やることを動詞で書き、下に「終わり」（終わったと言える状態）を1行付ける。** 終わりは、試験が通る・このコマンドでこれが出る・この人に送って返事をもらう、のように確認できる形にする。期限と、ほかの項目が前提になることは、その行に書く。
- **済みにするのは、「終わり」を全部確認してから。** 一覧に載せる前から実物で済みと確認できた依頼は、根拠を書いて済みにする（聞くことに回さない）。人やデータを待って終えられないものは「途中・待ち」にして、できた所・残り・誰の何をいつまで待つかを書く。
- **何をするかが決まっていない依頼（「スマホで見たい」「使いやすく」）は、作業にせず、「誰に何を聞く」の1件にする。** 聞いても作業にならないものは載せない。
- **軽く保つ。** 項目ごとの長いメモ、日程表、優先度の段、ラベルは追加しない。順番は並びで表す。1人で読み返して保てる長さ（1件に2〜3行）を超えたら、件は残して、その件のメモを削る。
- 待ちの項目があっても、ほかの項目は手元の材料で進める（去年の版を土台に案を作る、など）。聞くことは案と一緒に出す。

## 始めるとき（続きから）

- 「昨日の続きから」と依頼されたら、まずこのファイルを読む。次に実物（フォルダーの中身、コード、git のリポジトリなら履歴）を見て、ファイルと照らす。食い違えば実物を正として、ファイルを修正する（人が手で済ませて、印を更新していないことがある）。
- 期限の近いものと、待ちが解けたもの（届くはずだったものが届いている）を先に見る。
- ファイルが無く、前の会話も手元に無ければ、残っている物から分かることを書き出し、分からない残りは依頼した人に聞く。推測で埋めない。

## 止めるとき

- ファイルを更新してから止める。済んだもの、途中のもの（できた所と残り）、待っているもの、その日に出た新しい依頼が、全部ファイルにあるかを見る。
- git のリポジトリなら、ファイルの更新を作業と同じコミットに入れる。git のリポジトリでないフォルダーには、git を入れず、返事にも git の言葉を持ち込まない。
- 「今日はここまで」と止めるときの返事には、残りと、次に最初にやることを短く書く。ファイルの中身を全部写さない。
