# Web の画面の品質をそろえる

好みは人によって違うが、読めない・押せない・はみ出す・何が悪いか分からない画面は、誰にとっても悪い。ここに書くのは、測れる下限と、見た目を整えるときの進め方だけで、色や雰囲気の好みは決めない。AI に任せると、コードの上では整って見えても、ブラウザで開かずに渡しやすく、白い文字と明るい色のボタン、小さな注意書き、alert のままのエラーが残りやすい。

リポジトリにデザインの決まり（デザインシステム・色や余白のトークン・部品・Tailwind の設定）があれば、それを使う。以下は決まりが無い所の既定。文言の差し替えや1か所の直しを頼まれたら、そこだけを変え、ほかの直したい所は報告に1行で書く。

## 1. 作る前に

- 誰がどこで見るか（スマホが多いか、PC で長く使うか）と、画面で一番伝えたいこと・してほしいこと（締め切り、申し込み、数字）を、頼みと中身から読む。分からなければ1問だけ聞く。
- 元の中身（文・数字・日付・連絡先・ボタンの文言）は変えない。元に無い評価や結論（「好調」「要注意」）も足さない。変えたほうが良いと思う文は、報告で提案する。
- 外とつながる所（form の action・method・name、id、API の項目名、リンク先）は変えない。

## 2. 下限（どの画面にも）

数字は WCAG 2.2 と、日本語の公的な・広く使われるデザインシステム（デジタル庁、SmartHR）に合わせた目安。

- **言語と幅**：`<html lang="ja">`、`<meta name="viewport" content="width=device-width, initial-scale=1">`。拡大を止める指定（`user-scalable=no`、`maximum-scale=1`）は付けない。幅は固定せず `max-width` にし、幅 320〜390px で横にはみ出さない（長い URL や英数字は `overflow-wrap: anywhere`）。
- **文字の大きさ**：本文は 16px。補足・注意書き・ラベルも 14px を下限にする（小さくすると読まれない。大事な注意ほど小さくしない）。スマホで表が入りきらないときも文字は縮めず、表の箱の中で横に流すか、行ごとのカードに組み替える。入力欄の文字は 16px（15px 以下だと iPhone がフォーカスで拡大する）。
- **行と行の長さ**：本文の行間は 1.7 前後（見出しは 1.3〜1.5、1行のボタンは 1）。本文の幅は `max-width: 40em` 前後にし、PC で1行が 40 字を大きく超えないようにする。
- **色の差**：文字と背景は 4.5:1 以上（24px 以上か太字 19px 以上の大きい文字は 3:1）。ボタンの上の文字、placeholder、無効や補足の灰色の文字も含める。入力欄の枠やアイコンなど、文字でない部品は隣の色と 3:1。迷ったら色の値から比を計算する（目で決めない）。
- **書体**：日本語の書体を名前で並べ、最後に `sans-serif` を置く（例：`"Hiragino Sans", "Noto Sans JP", "Yu Gothic UI", Meiryo, sans-serif`）。英語の書体だけを指定すると、日本語は環境まかせになる。本文に `palt` や字間の詰めをかけない。
- **押しやすさ**：ボタン・リンクのボタン・チェックボックスの押せる所は 44×44px を目安にする（下限は 24px）。押せる物どうしは 8px 以上離す。文の途中のリンクは周りの文の大きさでよいが、連絡先のメールや電話のように1つで置くリンクは、padding で押せる所を広げる。
- **フォーカス**：Tab で動かしたとき、今どこにいるかが見える。`outline: none` にするなら、代わりの見える印（2px 以上で 3:1 の色）を `:focus-visible` に付ける。
- **色だけに頼らない**：必須・エラー・選択中は、色に加えて文字や記号でも示す。
- **画像**：意味のある画像に `alt`、飾りは `alt=""`。`width` と `height` を付けて読み込みで揺れないようにする。

## 3. 見た目の整え方（好みを足さずに）

- **階層**：一番伝えたいこと（締め切り・金額・押してほしいボタン）と、見落とすと困る注意（禁止・持ち物・取り消せないこと）を、大きさ・太さ・位置で一番目立たせる。文字の大きさは3段階ほど、色は文字の色・地の色・目立たせる色1つほどに絞る。目を細めて見て、一番目立つ物が一番大事な物か確かめる。
- **余白**：8px の倍数から3〜5段階を選んで使い回す（例：8・16・24・48）。関係の強い物（見出しと本文、ラベルと入力欄）は近く、別のまとまりは大きく離す。枠や背景色は、余白で分からないときだけ使う。
- **表と数字**：数字は右にそろえ、桁の幅をそろえる（`font-variant-numeric: tabular-nums`）。単位と期間を見出しに書く。
- **状態**：一覧やデータの画面は、読み込み中・0件・エラーを別の表示にする（読み込み中に「0件」と出さない）。0件には次にすることを書く。
- **ボタンの文言**：新しく作るボタンは、何が起きるかを動詞で書く（「OK」より「保存する」「削除する」）。今あるボタンの文言は変えずに、変えたほうが良ければ提案する。

## 4. フォーム

- 各入力欄に、常に見える `<label>` を付ける。placeholder は入力例だけにする（入力すると消え、ラベルの代わりにならない）。必須か任意かを文字で書く。
- `type`（email・tel・date・number）と `autocomplete`（name・email・tel・postal-code など）を合わせ、スマホで合うキーボードと自動入力が出るようにする。形式や字数の決まりは、入力の前にラベルの近くに書く。
- エラーは alert で出さず、その欄の近くに「何が・どう違い・どう直すか」を文字で出す（「メールアドレスに @ がありません」）。欄と文を `aria-describedby` で結び、`aria-invalid="true"` を付け、送信で失敗したら最初のエラーの欄にフォーカスを移す。項目が多ければ先頭に一覧も出す。ブラウザの `required` だけに任せる場合も、見える文で何が足りないかが分かるか確かめる。
- 入力した内容は、エラーで消さない。

## 5. 確かめてから渡す

コードを読んだだけでは、色の差・はみ出し・重なりは分からない。渡す前にブラウザで開く。

- 幅 390px（スマホ）と 1440px（PC）で開いて撮り、撮った画像を見る。手元にブラウザが無いときは、確かめていないと報告に書く。
- 測れる所は測る：横のはみ出し（`document.documentElement.scrollWidth > innerWidth`）、本文の文字の大きさ、使った色の組の比、小さい押せる所、Tab でのフォーカス。測り方の例は [references/check.md](references/check.md)。
- フォームは、空のまま送ったとき・形式を間違えたときに、どう出るかを実際に押して見る。
- 外とつながる所（action・name・リンク先）が元のままか、差分で見る。
- 直して撮り直すのは2〜3回までにする。好みの差（色合い・角の丸み）は直し続けず、撮った画像を頼んだ人に見てもらう。

## 6. 報告

撮った画像（スマホと PC）を添え、変えた所を下限の項目ごとに短く書く。測った値（例：ボタンの文字 5.2:1、はみ出し無し）、確かめていないこと、好みで決めた所（色・余白の段階）を分けて書く。
