# 書き出しの形

手順の 7（書く）で使う。聞いた中身は同じで、読み手に合わせて形を選ぶ。頼まれていなければ人が読む手順書にする。

## 共通の決まり

- 段の順に書き、各段に「やること」「判断の基準と数（理由）」「例外と対処」「誰が決めるか」を書く。理由は括弧で添える（「重さが200グラム以上違えば箱を開ける（詰め間違いが多いため）」）。
- 本人の言葉と聞き手の推測を分け、推測には「（推測）」を付ける。「もし〜なら」の答えは「（本人の想定）」と書いて、実例と分ける。
- 本人の「〜と思う」「〜じゃないですかね」、1回しかない経験は、決まった手順に書き上げない。「（本人の見立て）」「（1回の経験）」と添える。「ちゃんとした形ではない」を「無い」に縮めない。本人が「〜と思います」で言った約束や期限（「今週中には送れると思います」）も、決まった期限として書かず、本人の言葉で書く。
- 聞けなかった所は「未確認」と書き、推測で埋めない。
- 本人しか持っていないファイル・メモ・連絡先は、置き場所と、引き継ぎで移す期限を書く。
- 資料（マニュアル・画面の写し）で分かることは、手順書に写さず、資料を指す。

## 人が読む手順書

```
# 〇〇の手順（〇〇さんへの聞き取り、YYYY-MM-DD。本人の確認：済／未）

## この手順書について
- 誰が、いつ、何のために使うか
- 使う資料とファイル（置き場所）

## 全体の流れ
1. 〇〇 … 2. 〇〇 …（3〜6段）

## 段ごとのやり方
### 2. 〇〇（迷いやすい段）
- やること：
- 判断の基準と数：
- 例外と対処：
- 誰が決めるか：（自分で決めてよい範囲／上げる先と線）
- 新人が間違えやすい所：

## 注意（過去の失敗から）
- 〇〇（何が起きたか、今どうしているか）

## 未確認
- 〇〇（誰に聞けば分かるか）
```

## 頼んだ人あてのメモ（手順書と別に）

- まだ聞けていないこと（重い順）
- 本人以外の裏取りが要ること（慣習と言われた線、決まりの文書があるか）
- 本人がした約束（資料を渡す、ファイルを移す）と期限

## SKILL.md の形（頼まれたとき）

AI が読んで同じ仕事をする形。Agent Skills の形（agentskills.io/specification）に合わせる。

- frontmatter：`name`（小文字・数字・ハイフン、64字まで）と `description`（何をするか＋いつ使うか。仕事の名前と、頼むときの言葉を入れる。1,024字まで）。
- 本文の上に、作業の間ずっと守ること（判断の線、やってはいけないこと、上に上げる線）を置く。
- 段ごとの手順は、人が読む手順書と同じ中身を、AI が実行できる形（確かめてから次へ進む所、止まって人に聞く所）で書く。
- 未確認の所は「ここは人に確かめる」と書く。AI が推測で進めない。
- 本人しか持っていないファイルを AI が読む前提にしない。置き場所が決まるまで「未確認」にする。
