# 日本語に訳す

訳すのは、日本語の読み手が原文の読み手と同じことを分かり、同じことができるようにするため。AI の訳は、一文ずつは自然でも、原文の段落の順のまま並べて「自分は何をすればいいか」が読み手に分からないまま終わりやすい。画面の名前を勝手に日本語にして画面で探せなくしたり、「expect」を「予定」に強めたりもしやすい。

## 1. 訳す前に決める

- 誰が、どこで、何のために読むか（社内の利用者がポータルで読む、顧客にメールで送る、契約の確認に使う）。頼みと置き場から分かれば聞かない。
- 原文にどこまで沿うかを、用途で決める。
  - 契約・規約・法務・仕様・引用：構成も文の区切りも原文に沿う。言い換えや補足をしない。補足が要る所は訳注として分ける。
  - お知らせ・リリースノート・ヘルプ・社内向けの案内：原文の事実は全部残したうえで、読み手が使う形に組み直してよい。読み手の中で行動が違えば（何もしなくてよい人、管理者、特定の機能を使う人）、冒頭に「誰が何をするか」を短く置き、詳しい所へつなぐ。組み直しに使ってよいのは原文から言えることだけで、原文に無い手順や約束は足さない。
  - 社内に回すための訳で、頼んだ人が自社の事情（人数・契約の形・使っている機能）を伝えていれば、それを原文に当てはめた要点（「当社は東京のリージョンなので影響なし」「各部署の作業は不要」）を、原文の訳と分けて先頭に置く。要点は原文と伝えられた事情から言えることだけにし、誰かへの依頼（予算に入れる、相手に問い合わせる）は足さない。要点を置くかを聞き返さずに置き、報告で伝える。社外の差出人の挨拶や宛名（「ご担当者様」）は、回す相手に合わせて外すか、引用と分かる形にする。
  - 記事・宣伝の文：書き手の調子は残す。ただし英語の宣伝の型（「〜を発表できてうれしく思います」）は、日本語の読み手に合う形にする。

## 2. 落とさない・変えない

- 条件・数字・範囲・期限・対象を、原文から書き出して訳と照らす。「up to」「only」「by default」「not yet」「after」「per」のような語は、落ちると意味が変わる。
- 確からしさの強さを変えない。will（〜します）、expect・plan（見込み・予定。expect は「見込みです」「予定していますが確定ではありません」）、may・might（〜場合があります）、should（〜してください／〜のはずです、文脈で）、must（必ず〜）。お知らせの事実の文では、宣伝の強め（significantly・dramatically・excited）は、数字の裏付けがあれば数字で、無ければ強めずに訳す。
- 否定と例外（except・unless・not supported）は、訳した文の中で目立つ位置に置く。

## 3. 名前と用語

- 画面の名前・メニュー・ボタン・設定の場所は、読み手が見る画面の言語に合わせる。日本語の画面の表記を確かめられないときは、原文を残して訳を添える（「Billing > Invoices（請求 > 請求書）」）。推測で日本語の画面名を作らない。
- 製品名・機能名の固有名・コマンド・API・パス・コード・エラーの番号は原文のまま。
- カタカナ語は、読み手がふだん使う語に限る。そうでなければ訳語にする（retry → 再試行、encoding → 文字コード、workspace → 製品の中の呼び名に合わせる）。同じ原語は全体で同じ訳語にそろえ、迷う語は訳語の一覧を作ってから訳す。
- 単位・日付・時刻は日本の書き方にする（March 31, 2027 → 2027年3月31日。時刻にはタイムゾーンを添え、必要なら日本時間も書く）。

## 4. 日本語の文にする

- 「私たちは」「あなたは」「それは」は、日本語で要る所だけ残す。主語は、読み手が補えない所に書く。
- 「〜することができます」→「〜できます」、「〜を可能にします」→「〜できるようになります」。名詞を重ねた句は動詞の文に戻す。
- 長い英文は、条件と結果で2文に分けてよい。関係代名詞で後ろに付いた条件は、前に出す。

## 5. 訳したあと

- 原文と訳を1文ずつ照らし、落ちた条件・数字・例外と、足した説明が無いかを見る。組み直した場合は、原文の各文が訳のどこにあるかを確かめる。
- 分からない語・文脈に依る語は、推測で決めずに印（「（要確認：〜の意味）」）を付けて報告する。
- 報告には、組み直した所、原文のまま残した名前、選んだ訳語のうち迷ったものを短く書く。
