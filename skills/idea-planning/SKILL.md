# 企画を考える

企画の依頼には「チャットボットを入れたい」「勉強会を始めたい」のように、手段が入っていることが多い。AI は資料を読み、原因を突き止め、1つの案をよく作り込む。外しやすいのは絞り方で、次の形になる。

- 目的を書かないまま案を作る。何のための案かが読み手に伝わらず、案の良し悪しを測れない。
- 最初に思いついた形を1つ作り込み、形の違う案、やらない案、もっと小さくする案と比較しない。依頼した人は「ほかには無いのか」を自分で考えることになる。
- 形式・テーマ・やるかやらないかといった大きな選択を自分で決め、依頼した人に返すのが日時や担当のような細部だけになる。

フレームワーク（5W1H、SWOT など）は考えるのに使ってよいが、型の見出しを並べた企画書にはしない。読み手が要るのは型ではなく、目的と案の比較と推奨だから。

## 進め方

1. **目的を1文で置く。** 依頼の手段（チャットボット、勉強会）の向こうにある困りごとを、「〜を〜にしたい」の形で1文にし、企画の最初に書く。依頼や資料から読み取れれば、聞かずに置き、「目的は〜と読みました」と書いて進める。読み取れず、目的しだいで推奨が変わるときだけ、1つ聞く。聞くときも、いちばんありそうな目的で案を作り、問いと一緒に返す（返事を待つ往復を作らない）。
2. **前提を資料と既存の物で確認する。** 依頼の中の前提（「倍になった」「みんなやりたがっている」）を数字と照らす。同じことを前にやった記録、すでにある機能・制度・道具を探す。資料は、依頼されたときに渡されたファイルと会話に加えて、手元のフォルダーにある記録も読む。前提が食い違えば、目的の次に数字を添えて伝える。
3. **形の違う案を並べる。** 目的に届く道を2〜4つ、形が違うもの（作る／今あるものを修正する／方法を変える／人や時間を足す）から出す。その中に、やらない案かもっと小さくする案を1つ入れる。例：問い合わせが増えた → チャットボット／案内と導線を修正する／よくある質問を追加する／いまは何もせず件数を見る。
4. **比較して推奨案を1つ出す。** 目的にどれだけ効くか、費用と時間、戻せるか、を短い表か箇条で比較し、推奨を1つと理由を書く。推奨は提案で、決めるのは依頼した人。やるかやらないか、どの形にするかのように、目的や費用を左右する選択は「決めてほしいこと」として推奨を添えて返す。細部（日時、担当、置き場）は推奨の案の中に「仮」と書いて置いてよい。
5. **小さく試す順と、続けるかの目安を書く。** 最初の一歩（数週間・数回で終わる試し）と、効いたかを何で見るか（件数、参加人数など）、続けるかやめるかの線を書く。
6. **1枚に収める。** 企画は、目的・分かったこと・案の比較・推奨・最初の一歩・決めてほしいこと、で足りる。長いスケジュール表や、案ごとの細かい計画は、依頼した人が推奨を選んでから書く。

## 罠の無い依頼のとき

目的も条件も依頼と資料で決まっていて、選ぶのが店や日取りのような中身だけの依頼（日時と予算が決まった懇親会、決まった形の定例会の段取り）では、目的は1行、条件に合う案の比較と推奨、やることを期日つきで書けば足りる。目的を問い直す、やらない案を追加する、試しと続ける線を書く、は要らない（一回きりの催しには続けるかの判断が無い）。資料を読む途中で前提の食い違いが見つかったら、上の 1〜6 に戻る。

## 段取りを書くとき

日取りの決まった催しや切り替えの段取り（やることと期日）を書くときは、資料にある失敗（去年の反省、規程の期限）を拾うだけで終えない。書き終える前に「これが当日うまくいかなかったとしたら、原因は何か」を一度考える。資料にあることは放っておいても拾えるので、狙うのは資料に書かれていない所になる。

- まだ確定していないもの（人の返事、予約、申請）には、いつまでに確定させるかと、確定しなかったときの代わりの手を書く（講師の返事が来なければ、日をずらす・社内の人が話す）。
- 当日そこが崩れると全体が止まる所（配信、機材、鍵になる人）には、崩れたときに誰が何をするかを1行で置く（配信が落ちたら録画をあとで配る）。
- 資料に無い原因は、起きやすく手当てが安いものを2〜3個にとどめる。思いつく限りを並べない。

店を予約して集まるだけの会や、やり直しがきく段取り（上の罠の無い依頼の多く）では、この節は追加しない。確定していないものがあれば、やることの行に期限を添えるだけにする。この節を使うのは、外の人・機材・申請のように、崩れると当日に取り返せないものがある段取り。
