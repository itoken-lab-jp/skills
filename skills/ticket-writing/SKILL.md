# 作業の票を書く・分ける

票は、書いた人がいない所で、別の人や AI が拾って作るためのもの。拾った人が、同じ調べ直しをせず、どこまで作れば済みかが分かり、途中で壊さずに出せれば良い票になる。AI に任せると、仕様のファイルだけを見て、層ごと（DB・API・画面）に割った票を、順も済んだ条件も無しに立てやすい。元の票のコメントで覆った決定を見落とし、古い仕様のまま書くこともある。

チームやリポジトリに票の規則（ひな形、ラベル、粒度、親子の付け方）があればそれに従う。以下は規則が無い所の既定。

## 1. 書く前に集める

- 元の票（Issue など）は、本文だけでなくコメントと紐づく PR まで読む。本文と仕様のファイルは書いた時のままで、決着や訂正は後からの書き込みにある。仕様と食い違えば後の決定を採り、どちらを採ったかと出どころを票に書く。
- 関わるコードを読む。使える既存の関数・表・権限の仕組み・試験と、今の振る舞いの分かれ目（状態の値や、済んだかの判定）を見つけ、票に名前で書く。拾った人の探す手間が減り、二重の仕組みを作られずに済む。ファイルのパスや行番号は変わりやすいので、名前と場所の目安にとどめる。
- 外に約束している名前と形（公開の API、書き出すファイルの列、ほかのシステムが読む値）と、出し方（止めずに出す、新旧が同時に動く）を、README や docs で見ておく。分け方が変わる。

## 2. 会話やメモから仕様にするとき

- 時の順に読み、最後に決まった形で書く。覆った案は書かない（要るなら経緯に1行）。
- 決まったこと、やらないこと（今回の範囲の外）、決まっていないこと（誰がいつ決めるか）を分ける。
- 話に出ていないことを、決まったこととして追加しない。追加したほうが良いと思うことは「提案」として分けて書く。

## 3. 分け方

- 1票は、使う人（画面・API・バッチの先）から見て、ひとつの動きが確認できる単位にする。層ごとの票は、どれも単独では確認できず、最後につなぐまで動かない。
- 動きの票の最初は、端から端まで通る最小の形にする（画面で押す、処理が走る、結果が残る、を最小限）。回数の表示や細かい条件はあとの票で追加する。
- 作業を楽にする作り替えが要るなら、例外としてその票を動きの票より先に置く。作り替えの票は、振る舞いを変えず、今の試験が通ることを済んだ条件にする。
- 1票は、1人（AI なら1回の作業）で終わり、1つの PR で出せる大きさにする。小さい変更は1票にし、割らない。
- 各票に、先に済んでいるべき票を書く。票の道具に依存や親子の機能があれば使い、無ければ本文に「先に済むもの：#番号」と書く。

### 全体に及ぶ改名・型の変更

一度に全部を変える票や、フォルダーごとに割って途中が壊れる票にしない。

1. 追加する：新しい名前を、古い名前と両方使える形で追加する。DB の列は、いきなり改名せず、列を追加する → 両方に書くコードを出す → 既存の値を写す、の順にし、そのあとで読む側を移す。止めずに出す（新旧のコードが同時に動く）所では、改名を一度にすると切り替えの間に壊れ、写してから両方に書く順だと、その間の書き込みが新しい列に入らない。
2. 移す：呼び出し元を束（フォルダー・パッケージ）ごとに新しい名前へ移す。束ごとに1票で、どの票のあとも試験が通る。束の分け方は、古い名前をコードで探して数え、票に何か所あるかを書く。
3. 消す：古い名前と列を消す。移す票すべてのあとに置く。

外に約束している名前（公開の API の項目、書き出すファイルの列名）は、変えると外が壊れる。中だけ変えて外はそのまま出すか、変えるなら別の票にして依頼した人に確認する。

## 4. 票の中身

```
## なぜ
（使う人から見た困りごと。元の票へのリンク）

## やること
（使う人から見た振る舞い。使う既存の物：関数名・表・権限）

## 済んだと言える条件
- [ ] （何をすると何が起きるか。起きてはいけないことも）
- [ ] （足す試験）

## 先に済むもの
（#番号、または「無し（すぐ始められる）」）

## 決まっていないこと・範囲の外
（無ければ書かない）
```

済んだ条件は、拾った人と見る人が同じ判定になる形で書く（「ちゃんと動く」ではなく「出荷前の注文には取り消しのボタンが出て、出荷済みには出ない」）。時刻にはタイムゾーンを、件数や回数には上限の扱いを添える。

## 5. 決まっていないこと

- 自分で決めない。決まるまで作れない部分は別の票に分け、「待ち：誰の何（例：法務の返事）」と書く。残りの票は先に進められる形にする。
- 仮で進めるしかない所は、仮であることと、決まったら修正する所を書く。

## 6. 立てる・報告する

- 「立てておいて」と依頼されたら立ててよい。票は閉じれば戻せる。分け方に迷う大きな判断（範囲を広げる、外の約束を変える）だけ、立てる前に聞く。
- 元の票は閉じず、本文を書き換えない。新しい票から元の票へリンクし、親子の機能があれば子にする。元の票に、立てた票の一覧をコメントで残すと追いやすい。
- 報告は、立てた票の一覧（番号・題・順）、採った決定とその出どころ、未決と誰待ちかを短く書く。
