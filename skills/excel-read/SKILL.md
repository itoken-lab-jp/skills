# Excel を読む

Excel は、Python などでスクリプトを書かずに、この Skill に入っている道具 `excel-read` で読む（スクリプトは依存を入れる・走らせる・修正するの往復で遅い）。.xlsx・.xlsm は行ごとに読みながら出すので、大きいシートでもメモリはほとんど増えない（セルが行の順に並んでいないシートだけは丸ごと読む）。読み取りのためのスクリプトは書かない。出した CSV や JSON の集計は、量が少なければそのまま読んで行い、多ければ SQL で集計できる道具（DuckDB など）を使う。

## 道具の場所

この SKILL.md と同じフォルダーの `scripts/` に、OS ごとの実行ファイルがある。PATH には入っていないので、フルパスで呼ぶ（パスに空白があれば引用符で囲む）。実行の権限と Mac の署名は付けてある。

- Windows（x64）：`scripts/windows-x64/excel-read.exe`
- Mac（Apple シリコン）：`scripts/mac-arm64/excel-read`
- Linux（x64）：`scripts/linux-x64/excel-read`

この Skill のフォルダーはエージェントごとに違う（Claude は `~/.claude/skills/excel-read`、Codex は `~/.agents/skills/excel-read`、Antigravity のアプリと IDE は `~/.gemini/config/skills/excel-read`、Antigravity CLI は `~/.gemini/antigravity-cli/skills/excel-read`、Kiro は `~/.kiro/skills/excel-read`）。中身はどれも同じ。上の3つの実行ファイルに当たらない機械（Intel の Mac、ARM の Windows など）では動かないので、下の「読めないとき」に進む。

以下、例ではフルパスを `excel-read` と略す。`excel-read --help` で全部のコマンドと引数が出る。

## 共通の約束

- 出力は標準出力に UTF-8（BOM なし）で出る。`--out ファイル` を付けると、どのコマンドでもそのファイルに書き、標準出力には出さない（読むファイルと同じパスは断る）。大きな出力は `--out` で書き、文脈に入れるのは要る所だけにする。
- **Windows の PowerShell**：コンソールの文字コードが UTF-8 でない（932 など）と、パイプで受けた出力も標準エラーの文も化ける。呼ぶ前に `[Console]::OutputEncoding = [Text.Encoding]::UTF8` を実行し、出力は `--out` で書いてそのファイルを読む（Windows PowerShell 5.1 の `>` は UTF-16 のファイルになるので使わない）。
- **標準エラーも必ず読む**。終了コードが 0 でも、隠した行を出した・数の結合を埋めた・0行だった・表示形式に単位がある、などの注意を `excel-read: 注意：…` で出す。
- `--sheet` を省くと、表示されている最初のワークシートを読む（隠したシートは飛ばす）。
- 範囲（`--range` と設定の `range`）は `A1:H50`・`A4:F`（そのシートで使っている最後の行まで）・`A:F`・`A4`（そこから右下の端まで）の形。`$A$4:$F$12` の `$` は無視する。
- 値の書き方：数はそのまま（整数は小数点なし）、日付は `2026-10-30`、日時は `2026-10-02T14:05:00`（表示形式でなく値で分けるので、日時の列でも 0 時ちょうどのセルは日付だけで出る）、時刻だけは `09:30:00`、時間の長さは `-01:20:00` のように符号付き、真偽は `true`・`false`、セルのエラーは `#DIV/0!` などの文字。空のセルと、空の文字（`""` を返す式など）は `null`（CSV では空）。
- 終了コード：0 は成功、1 は読めない（ファイル・シート・設定の誤り）、2 は使い方の誤り。理由は標準エラーに出る。.xlsx は読みながら書くので、1 のときは出力（`--out` のファイルも）が途中までのことがあるので、その出力は使わない。標準エラーの理由を見て、指定の誤りなら修正して走らせ直し、ファイルが読めないなら下の「読めないとき」に進む。

## 進め方

1. **シートを見る**：`excel-read sheets 帳票.xlsx`。1行1シートの JSON で出る。
   ```
   {"sheet":"台帳","state":"visible","used":"B1:G6","merges":0,"tables":[{"name":"売上表","data":"B4:D6"}],"hidden_rows":0,"hidden_cols":0,"filter":null}
   ```
   名前・`state`（`visible`・`hidden`・`very_hidden`）・使っている範囲・結合セルの数・Excel のテーブル・隠した行と列の数・オートフィルターの範囲。グラフだけのシートなどには `kind`（`chart` など）が付く。.xlsx・.xlsm 以外では `tables`・`hidden_rows`・`hidden_cols`・`filter` が `null`（読めない）、結合を読めない形式では `merges` が `null` で、理由が `merges_note` に出る。隠したシートは、ユーザーが見ている表ではないことが多いので、読むなら読んだと報告に書く。`hidden_rows` か `filter` があるシートは、手順4で隠した行の扱いを決める。目的のシートが名前で分からなければ、次の手順で候補を見比べる。

   `tables` に目的の表があれば、手順2から4を飛ばして `excel-read table 台帳.xlsx --table 売上表` で読む（Excel のテーブルは、挿入のテーブルや Ctrl+T で作った名前の付いた表。Power Query の読み込み先もこれになる。見出しとデータの範囲がファイルに書いてあるので、範囲を決めなくてよい。集計の行は入れない）。
2. **形を見る**：`excel-read dump 帳票.xlsx --sheet 月次報告 --format grid`。1行目に `# {...}`（シート・使っている範囲・出した範囲・結合・範囲の中の隠した行の番号と列・フィルター）、2行目に列の文字、そのあと行ごとにタブ区切りで出る。結合セルは、左上のセルに値が出て、覆われたほかのセルに `^A4`（A4 を左上とする結合の中）と出る。空のセルは空。
   ```
   # {"sheet":"月次報告","used":"A1:F16","range":"A4:F6","merges":["A4:A5",...],"hidden_rows":[],"hidden_cols":[],"filter":null}
   	A	B	C	D	E	F
   4	部門	担当	売上	^C4	^C4	備考
   5	^A4	^B4	計画	実績	差額	^F4
   6	営業1部	佐藤	100	120	20	
   ```
   `grid` も `jsonl` も、範囲の先頭から 200 行で止まり、最後に `{"truncated":true,"next":"A201:F500",...}`（`grid` では先頭に `# `）と続きの範囲が出る。続きは `--range A201:F500` で見るか、`--max-rows` で行数を増やす。列が多いシートは、まず `--range A1:Z30` などで上の方だけを見て、見出しを探す。
3. **値・式・表示形式を見る**（要るとき）：`excel-read dump 帳票.xlsx --range D5:F20`（`--format` の既定は `jsonl`）。1行目は `grid` の `# ` の後と同じ情報で、外部リンクのあるブックでは `"links":{"[1]":"file:///C:/共有/前年.xlsx"}`（式の `[1]` が指すブック）も付く。2行目からは空でないセルを1セル1行で出す：`{"a":"E7","v":-20,"f":"D7-C7","nf":"#,##0,\"千円\""}`。番地 `a`・値 `v`・式 `f`（先頭の `=` は付かない）・表示形式 `nf`（標準以外で、値のあるセルのとき。.xlsx・.xlsm だけ）・結合の範囲 `m`（`"m":"C4:E4"`。左上のセルにだけ付く）。値は Excel が保存したときの計算の結果で、計算し直してはいない。
4. **表に整える**：`dump` で見出しの行・データの範囲・捨てる行（小計・合計・注記）を読み取り、`table` で出す。見出しが1行で捨てる行の無い表なら引数だけで足りる：`excel-read table 一覧.xlsx --sheet 一覧 --range A3:H`。見出しが複数行の表と、捨てる行のある帳票は、下の設定ファイルを書いて `excel-read table 帳票.xlsx --config 帳票.table.json`。
   - 次のときは、先に [references/table.md](references/table.md) の「手順4の細部」を読む：1つのシートに表が複数ある、同じ形のシートが並ぶ、見出しの名前が崩れる、データの部分に結合セルがある（金額が重なる）、隠した行がある、雛形の行や繰り返しの見出しがある、出力の形（CSV・JSON・BOM）を変える。
5. **確認する**：
   - 単位：標準エラーの「表示形式のある列」を見る。値は生の数で、画面で `1,234千円`（`#,##0,"千円"` は 1000 で割って見せている）・`10%`・`$12`・`1.500g` と見えるセルも `1234000`・`0.1`・`12`・`1.5` と出る。同じ表に `$` と `¥` の列が並ぶなど、単位が表示形式にしか無い列は、列の名前に単位を書き足して報告し、単位の違う列を足し合わせない。分からなければユーザーに聞く。
   - 数：出した表の行数を数え、帳票にある合計か小計の行（`dump` で見える）の1つを、出した表から足し直した数と突き合わせる。合わなければ、どの行を取りこぼした・重ねたか（隠した行・重なった結合・雛形の行）を `dump` で探し、設定を修正する。修正できなければ、食い違いをそのまま添えて報告する。

見出しの行や捨てる行が `dump` を見ても決められない（どれが明細でどれが小計か分からない、など）ときは、`grid` の該当の行を見せてユーザーに1回聞く。決められるときは決めて進め、何を捨てたかを報告に書く。

同じ形の帳票を何度も読むなら、設定ファイルを残すとよいかをユーザーに聞き、良ければそのファイルを扱っているリポジトリやフォルダーに置く。次からはそれを渡す。

## 設定ファイル（table）

見出しが複数行の表と、捨てる行のある帳票は、設定ファイル（JSON）を書いて `table --config` に渡す。書く前に [references/table.md](references/table.md) の「設定ファイル（table）」を読む（`range`・`header_rows`・`drop_rows`・`stop_when`・`fill_merged` などの書き方）。

## Power Query と VBA

`excel-read queries ブック.xlsx` で Power Query の M のコードを、`excel-read vba ブック.xlsm` で VBA のコードを出す。読むだけで、実行も更新もしない。出力を読む前に [references/queries-vba.md](references/queries-vba.md) を読む（出力の形と対応する形式）。

## できないこと

式は計算し直さず、保存された計算の結果だけを読む（式の列に値が無ければ、Excel で開いて保存し直してもらう）。表示の文字そのもの、文字の色や塗り、図形・グラフ・画像・コメント・ピボットの定義、パスワード付きのファイル、パスワードで保護した VBA のコードは読めない。値が空・表示と違う・形式が古いときは [references/limits.md](references/limits.md) を読む（形式ごとに読めないもの、隠した行・結合・表示形式を含めた一覧）。色で意味を付けた表に見えたら、ユーザーに聞く。

## 読めないとき

- 「開けません」で止まり、拡張子が合っていそうなら、拡張子と中身の形式の食い違い（.xls という名前の .xlsx、CSV に .xls と付けたもの）か、暗号化（パスワード、会社の秘密度ラベル）を疑う。暗号化されたファイルはユーザーに外してもらうか、Excel で開いてもらう。
- 実行ファイルが起動しない（アクセスが拒否された、ウイルス対策が止めた）ときは、業務用の PC の制限（AppLocker・Defender など）のことがある。外そうとせず、ユーザーに伝える。

道具がエラーで止まった、合う実行ファイルが無い、出た表が帳票と明らかに食い違う、のどれかなら、理由（出たエラーや食い違い）をユーザーに伝えてから、ほかの手段に移る。どの手段が使えるかは、全体の指示ファイル（`~/.claude/CLAUDE.md`・`~/.codex/AGENTS.md` など）にその PC の事情が書いてあれば従う。Excel が入った Windows なら PowerShell から Excel の COM で開く手があるが、読み取り専用で開き、保存せずに閉じる。
