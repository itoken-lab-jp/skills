# 試作で確かめる

試作は、決める前に動かして確かめるための、捨てるコード。値打ちは試作そのものでなく、それで決まったことにある。

AI は試作そのものはうまく作る。1つのファイルで開ける、業務の言葉のボタン、状態が見える、本番のコードに触らない、は言われなくてもできる。外すのは試作の前後で、次の形になる。

- 試作を触った人が「こう決めた」と言っても、仕様書や票に書かない。「頼まれていないので」と聞いて止まり、決定は会話の中にしか残らない。来週の実装者はそれを知らない。
- 試作のファイルを、コミットもせず消しもせず置いたまま「どうするか決めてください」と返す。
- 画面の案を、何もない別のページに並べる。まわりの欄と並んだときの詰まり方や長さが分からず、どの案も良く見える。
- 決まった案を本番に入れるとき、試作の説明を消すだけで、何に決めたか・なぜかをどこにも残さない。

## 作る

1. **確かめる問いを置く。** この試作で何を決めたいのかを1〜2文で、試作の画面の上と、渡すときの返事に書く。頼みや仕様の「まだ決めていないこと」から読み取れれば聞かずに置く。問いが、動きや状態の持ち方（この流れで困る場面は無いか）なのか、見た目（どう見せるか）なのかで作る物が変わるので、どちらか分からず、読み違えると作り直しになるときだけ1つ聞く。
2. **捨てる作りにする。** 本番のコード・データ・保存の処理につながない。試験、エラー処理、先を見越した設定や抽象は足さない。試作と分かる名前と置き場にし、画面にも試作と書く。開くのに要るのは、ファイルを開くか、コマンド1つまで。
3. **動きの試作は、決まっていない点を切り替えて比べられるようにする。** 紙の上では分かりにくい場面（順番が入れ替わる、期限をまたぐ、2回目の操作）を実際に通せるよう、日付や時間を進める手段を付ける。未決の点は、両方の決め方を画面で切り替えられるようにする。試作のために自分で仮に置いた前提は、画面に「仮」と書く。
4. **画面の試作は、今の画面の中で切り替える。** 案は3つ前後で、配置・まとめ方・主な操作が違うものにする（色や文言だけの違いは案に数えない）。別のページを作らず、今のページの中の、その欄の場所に案を出し、URL のパラメーターなどで切り替える。何も付けずに開いたときは今のまま。案からは本物の保存に書かない。新しい画面で、入れる先のページが無いときだけ、別のページにする。
5. **渡すとき**は、開き方、確かめてほしい問い、案や場面の名前を短く書く。自分の推しを添えてよいが、決めるのは触った人。

## 決まったあと

6. **決まったことは、聞かずに書く。** 触った人が決めたことを言ったら、その返事の中で、仕様書・票・設計のメモの「未決」を、決まった内容と理由に書き換える。書く場所が無ければ、仕様のそばに短いメモを作る。決まったことを残すのは試作の仕事の一部で、頼まれるのを待たない。「まだ決めない」と言われたら、今出ている見立て（どの案が良さそうか）と、誰がいつ決めるかを同じ場所に書く。書くのは相手が言った範囲までにする。相手が言っていない理由や了解（「この欠点は承知のうえ」など）を足さない。自分に気がかりが残るなら、決定とは分けて「気がかり」として1行書き、返事でも一度だけ伝える。
7. **試作の行き先を自分で決めて、行ったことを伝える。** 既定は、試作を main に入れず、名前で試作と分かるブランチにコミットして、決定を書いた文書からそのブランチの名前を引く（後で「なぜこう決めたか」を見返せる）。ブランチを push していなければ、ほかの人や別の機械からは開けないので、手元だけにあることを返事と文書に書く（push するかは、リポジトリの決まりと頼まれ方に従う）。git を使っていない、ブランチを切れない事情があるときは、試作のフォルダーに置いたままにして、置き場と「本番ではない」ことを文書に書く。main にコミットするよう頼まれていなければ、決定を書いた文書は書き換えたまま置き、コミットしていないことを伝える（試作のファイルを試作のブランチへコミットするのは main を変えないので、してよい）。試作を手元の置き場から移したら、もう一度開く方法（ブランチの名前とファイル）を返事に書く。リポジトリにコミットやブランチの決まりがあれば、そちらに従う。
8. **本実装は、頼まれてから。** 決まったからといって、試作のコードを本番に入れ始めない。

## 決まった案を本番に入れるとき

- 試作のコードをそのまま移さない。試作で省いていたもの（保存、前からあるデータの読み込み、空や異常の場合）を、本番のやり方に合わせて書く。
- 落ちた案、切り替えの仕組み、試作の印を本番のコードから消す。
- 何に決めたか・なぜか・落ちた案は何だったかを、コミットの文か文書に残す。試作の説明の文書は、消すだけにせず、決定の記録に書き換える。落ちた案を見返せる場所（コミットやブランチ）があれば、そこを引く。
