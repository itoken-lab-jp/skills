# 検証の走らせ方

SKILL.md の「依頼方法」の、読み取り専用で起動するときの細部。

- 読み取り専用で起動すると、検証コマンドは走らないか、書き込みを伴うもの（テストやビルドの多く）が落ちる。そのときは依頼する側が走らせ、コマンド・終了コード・出力の要所・そのときの HEAD を渡す（コマンドが走らない起動なら、「既存」を決めるための、変えたファイルの `git blame -s <変更全体の起点>..<終点> -- <ファイル>` の出力も。起点より前の行には `^` が付く）。レビュアー自身に走らせたいなら、書き込みを作業ツリーと一時ディレクトリに限れる起動（Codex の `-s workspace-write` など）で、同じ SHA から git で作った使い捨ての worktree（`git worktree add --detach <絶対パス> <SHA>`）に向けて走らせ、終わったら worktree ごと捨てる。worktree には git の管理外のもの（`node_modules` などの依存）が入らず、その起動は既定でネットワークも止まるので、worktree を作ったら、レビュアーを起動する前に、その worktree で依存を入れる（`npm ci` など）。
