# 数字や表示がおかしいとき

ここに挙げるずれは、どれもエラーが出ない。DAX のクエリで全体の値が合っていても起きる。作者の環境では確認していない観察で、版と日付の記録は無い。

## メジャーを作る前にユーザーに確認する

- 何を足すと合計になるか。内数（「うち〜」の行や列）を二重に足していないか。
- 版（ファイルの更新日など）ごとに積んだ表なら、版の順番を何で決めるか。
- 元のデータの誤りを補正する依頼なら、補正は元のデータの側で修正するもので、Power Query での補正は元が直るまでのつなぎだと伝える。

## 合計が合っているかを見る

足してよいメジャー（金額・時間・件数の合計）は、切り口ごとに足し上げた値が全体と一致するかを DAX で見る。

```dax
EVALUATE
ROW(
    "全体", [売上金額],
    "切り口ごとの和", SUMX(VALUES('売上'[部門]), [売上金額])
)
```

率・平均・重複を除いた件数は、正しくても一致しないので、この見方は使わない。

## 症状ごとの原因と修正方法

| 症状 | 原因 | 修正方法 |
| --- | --- | --- |
| 切り口（フィールドパラメータ）を切り替えると合計が変わる | 版ごとに積んだ表で「最新」を `MAX(更新日)` で決めていて、最新の版に無い項目の行で古い版の値が混ざる | 版の番号の計算列（`RANKX`）を作り、版のフィルタだけで最新を決める。同じ更新日のファイルが 2 つあると順位が重なるので、先に確認する |
| ほかのビジュアルで絞ると、軸の月が消える | auto-exist（絞った列と同じ表の列の組み合わせだけが残る）。0 を返すメジャーに変えても直らない | 月だけの表を別に作って軸をそちらにし、その表にある月だけを 0 で埋める |
| 選んでも合計が動かず、一部だけが濃く表示される | 縦棒・横棒の既定の相互作用が強調表示になっている | 相互作用を「フィルタ」にする |
| 凡例のある折れ線で、版が変わるたびに線の色がずれる | 凡例に日付を置いている（版が変わると凡例の値が変わり、色の割り当てが付け替わる） | 凡例には版の番号（上の行の計算列）を置く。fx（条件付きの書式）で色を固定する手は、凡例のある折れ線では線の色に出ないので使えない |
