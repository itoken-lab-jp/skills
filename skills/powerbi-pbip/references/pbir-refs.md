# PBIR の参照を書き換える

列やメジャーの名前を変えたとき、ページを複製して参照を差し替えるときの手順。Authoring MCP の `Rename` も、Desktop の外で TMDL を修正するのも、レポートの `visual.json` の参照を追従させない。書き漏らしは Desktop で開くまで見えない。

## 参照が書かれている3か所

| どこ | 例 | 参照先がモデルに無いとき |
| --- | --- | --- |
| 構造の参照 | `{"Expression": {"SourceRef": {"Entity": "表"}}, "Property": "名前"}`。フィルターの `From` の別名を通るもの、階層（`Hierarchy`）も含む | 壊れる。修正する |
| フィールドパラメータの選択値 | `'''表''[名前]'` | 壊れる。修正する |
| `queryRef`・`queryRefs`・`metadata` の文字列 | `"表.名前"`、`"Sum(表.名前)"`、`"表.日付.Variation.…"` | Desktop では開けることがある。ただ列の幅などの書式の指定が当たらなくなるので、名前の変更に合わせて修正する |

- 3つ目の文字列は、モデルにある表の名前で始まるものだけを対象にし、名前の後ろはその表の列・メジャー・階層との最長一致で読む。
- フィルターの別名は 1 つの表しか指せない。別名を通る参照の移し先が表ごとに分かれるときは、書き換えずにユーザーに相談する。
- タイトルや表示名（`displayName`・`nativeQueryRef`）の文字列を置き換えるときは、参照・選択値・フィルター・`visualType` には掛けない。複数の置き換えは一度に行う（A→B と B→C を順に掛けると、A が C になる）。
- ライブ接続のレポート（モデルの定義が手元に無い）は、参照をモデルと照らせない。書き換えずに止まり、ユーザーに伝える。

## 書き換えの手順

1. モデルの変更を済ませ、Desktop で保存して、Desktop をすべて閉じる（開いたままだと、Desktop の保存で書き換えが上書きされる。どのファイルを開いているかは窓のタイトルでも確認しきれない）。自分で開いた Desktop は自分で閉じ、ユーザーの Desktop は閉じてもらう。
2. レポートのフォルダーを丸ごと一時フォルダーへ複製する（書き換えに失敗したら、これで戻す）。
3. 書かずに、何をどう変えるか（旧 → 新）を全部一覧にして読み、ユーザーにも見せる。変える参照の先がモデルに実在するか（3か所とも）を照らし、新しく壊れる参照が1つでもあれば、何も書かずにユーザーに報告する。一度も当たらなかった指定があれば、綴りの誤りを疑い、修正して一覧を出し直す。
4. 書く。書いた直後にも、2 とは別のフォルダーへ複製を取る（あとでユーザーが Desktop で手直ししたとき、その差分を取り出して、ほかのページへ同じ修正を広げる比較元になる）。
5. JSON が読めるか、参照がモデルに実在するか、ページ名・相互作用・グループの参照先があるかを確認する。レポートの CLI の `validate` が使えれば一緒に走らせる（[report-cli.md](report-cli.md)）。
6. Desktop で開き直し（自分で開いたものは自分で、ユーザーのものはユーザーに依頼する）、変えたページを撮るか、ユーザーに画面で見てもらう。

同じ書き換えを何度もするなら、その場でスクリプトを書き散らさず、上の手順を守る道具を1本にしてリポジトリに置く（その場で書くと、2 日の手直しのあいだに置き換えのスクリプトが 5 本でき、エージェントごとに違う置き換えをした例がある）。

## ファイルで修正しないもの

- 1〜2 個のビジュアルの書式やフィールドの差し替え。ユーザーに Desktop で修正してもらうほうが早くて安全。ファイルで修正するのは、ページの複製、多くの参照にまたがる変更、ビジュアルのあいだの相互作用の設定。
- 書式を指標に合わせること（表示単位・小数の桁・固定の色）。金額のページから時間のページを複製すると、百万単位の表示が残る。文字列の置き換えで数値や色を替えると、部分一致で別の値まで変わるので、ユーザーに Desktop で修正してもらう。
- スライサーの初期選択、フィールドパラメータの並び、配置や余白の数値。業務の判断や見た目の調整が要るので、ユーザーに Desktop で修正してもらう（名前の変更に合わせた選択値の書き換えは、上の表のとおりファイルで修正する）。
