# コードで図とスライドを作る

SVG や HTML で図を書くと、中身（部品・つながり・数字）は合っているのに、置き方で崩れる。座標を頭で計算して置くので、描いた結果は見ないと分からない。よく残るのは次の崩れで、コードを読み直しても見つからない。

- 矢印のラベル（「書き込み」「差し戻し」）が線の上に乗る。戻りの線や枠線が文字を通る。
- 長い名前が箱からはみ出す（SVG の文字は自動で折り返さない）。
- スライドに全部を詰めて、文字が小さくなるか、枠の下に切れる。
- Mermaid のラベルやメッセージに、構文に当たる記号（`;` `(` `"` など）をそのまま書いて、GitHub などの置いた先で、図の代わりに構文エラーが出る。
- 画像にする道具（`convert` など）が1つ動かないと、見るのをあきらめて「確認してください」と渡す。

## 進め方

1. **伝えることを1つ決め、入れるものを選ぶ。** 図は、見た人に分かってほしいこと（「注文は3つのサービスを通って DB に入る」）を1文にし、それに要る部品とつながりを元の資料から拾う。資料に無い部品・数字は足さない。スライドは、1枚に言うことを1つにし、見出しをその結論の文にする（「第3四半期の振り返り」より「売上は達成、ただし A 社を除くと前年割れ」）。入りきらないときは、文字を縮めずに、載せるものを減らすか枚数を分け、省いたものを返事に書く。元の資料の数字は、計算し直して書き換えない（自分の計算と合わないことに気付いたら、元の数字のまま載せ、返事で伝える）。
2. **作る先の指定を読み、大きさと文字の下限を先に決める。** 作る先（会社のテンプレートの .pptx、貼る先の資料やサイト）にフォントと色の指定があれば、書く前に読み、値を写さずに参照して使う（.pptx はテーマ、CSS は変数）。自分で選ぶのは指定が無いときだけ。読みにくい所だけ、同じテーマの色の明るさを変える。指定どうしが食い違えば、テーマに合わせて作り、返事で伝えて聞く。大きさの指定が無ければ、資料に貼る図は幅 1200px 前後、スライドは 1280×720（16:9）、見出し画像は指定の大きさ。文字は、図で 14px 以上（補足でも 12px）、映すスライドの本文は 24px 以上（表や注記でも 18px。.pptx では本文 18pt 以上、表や注記でも 14pt）、縮めて一覧に出る見出し画像の題は 56px 以上。下限を割らないと入らないなら、手順 1 に戻って減らす。
3. **重ならない置き方で書く。**
   - 箱は格子にそろえて置き、箱の幅は中の文字から決める：全角1字は font-size と同じ幅、半角はおよそ半分で数え、左右それぞれに 16px 以上の余白を足す（見る人の PC では別のフォントで描かれ、文字の幅が変わるので、ぎりぎりに詰めない）。入らない名前は、箱を広げるか、SVG なら `<tspan>` で意味の切れ目に手で改行する（1行目に名前、2行目に補足）。
   - 箱と箱の間は、ラベルを置く矢印なら 80px 以上あける。矢印のラベルは線の上に乗せず、線の中ほどの横（横の線なら上に 6px 以上、縦の線なら右に 8px 以上）に置く。斜めの線に沿って文字を回さない。線は縦と横だけで引くと、ラベルの置き場が決まる。
   - 戻りの線・迂回の線は、箱の列の外側に通り道を取り、線ごとに 20px 以上ずらす（同じ行き先の線は、途中で1本に合流させてよい。そのときは、どの箱から出た線かを追えるよう、出口ごとに向きの矢印かラベルを付ける）。箱や別の線のラベルの上を通さない。
   - 1つの部品から多くの部品へ引く線（監視・ログなど）は、1本ずつ引かずに、相手をまとめの枠で囲んで枠に1本引くか、印と凡例で表す。
   - 日本語のフォントの指定が無いときは、 `font-family` に複数の候補と総称を書く（例：`"Noto Sans JP", "Hiragino Sans", "Yu Gothic", Meiryo, sans-serif`）。
   - HTML では `<html lang="ja">` にし、見出しや短い文には `word-break: auto-phrase`（文節で折り返す。対応するブラウザだけに効く）を付けて、「理／由」のような語の途中の折り返しを減らす。
   - HTML のスライドは、1枚を固定の大きさの箱（1280×720px、`overflow: hidden`）にし、中身を flex や grid で枠いっぱいに配る（下半分が空いたままにしない）。PDF で配るなら `@page { size: 1280px 720px; margin: 0 }` と、1枚ごとの改ページ（`break-after: page`）を書く。
   - 見出し画像など題が長い物は、折り返しを成り行きに任せず、意味の切れ目（「：」の後、助詞の後）で自分で行を分ける。
4. **描いて、検査にかけ、画像を開く。** 書いたら毎回、この SKILL.md と同じフォルダーにある検査 `scripts/layout-check.mjs` を走らせる（Node 22 以上と、Chrome・Edge・Chromium のどれかが要る。npm の依存は無い）。

   ```
   node <この Skill のフォルダー>/scripts/layout-check.mjs 図.svg            # 描いた PNG の場所と、指摘を出す
   node <この Skill のフォルダー>/scripts/layout-check.mjs deck.html --pdf deck.pdf   # スライド：PDF のページ数と用紙も出す
   node <この Skill のフォルダー>/scripts/layout-check.mjs README.md --width 900       # Mermaid：```mermaid のブロックを1つずつ描く
   ```

   指摘（文字どうしの重なり、枠からのはみ出し、線が文字を通る、図の外、小さい文字）は、描いた画像の左上からの座標（px）つきで出る。指摘を直して、走らせ直す。直すときは、当たっている文字か線を動かす・箱を広げるだけにし、関係ない所を作り直さない。次に、出力にある PNG（一時フォルダーに出る）を、画像を読める道具（Read など）で自分で開いて、機械で分からない所を見る：線がからまって追えない所、矢印の向きと行き先、余白の偏り、日本語が □ になっていないか、手順 1 の1文が図から読み取れるか。スライドを PDF にするときは、ページ数がスライドの枚数と同じで、用紙が 16:9 かを出力で確かめる。
   - 「検査して直す」は3回までを目安にし、それでも残った崩れは、どこに何が残ったかを返事に書く（「確認してください」と丸ごと渡さない）。
   - 検査が走らないとき（ブラウザが無い）は、ほかの手段で画像にして見る：Playwright、ブラウザのヘッドレスの `--screenshot`、`rsvg-convert` など。1つ失敗しても次を試す。どれも無いときだけ、見ていないことを返事に書く。
   - PNG を頼まれたとき（見出し画像）も、SVG か HTML で書いて、この検査が作る PNG を渡す（`--out header.png`。HTML は `--width` と `--height` を画像の大きさにする）。
   - わざと重ねて見せる所（悪い例の図）は、その要素に `data-layout-ignore` を付けると検査から外れる。
5. **返事は短く。** 保存した場所、図の読み方か省いたものを1〜2文、残った崩れがあればそれ。作り方の説明は要らない。

## Mermaid で書くとき

- **どちらで書くか。** 置く先が Mermaid を描く所（GitHub・GitLab の Markdown、Notion、Zenn など）で、流れ図・シーケンス図・ER 図・状態の図なら、Mermaid で書く（配置は道具が決めるので、箱どうしは重ならず、直すのも文字を書き換えるだけで済む）。形式を指定されたら、それに従う。Mermaid を描かない資料やスライドに貼る図、層や位置に意味がある構成図、見出し画像は、SVG か HTML で書く。
- **Mermaid の記号を逃がす。** 元の資料の言葉に記号があっても、言葉は変えずに逃がす。
  - 流れ図のラベルは、二重引用符で囲む：`a1["決済する (Stripe: PaymentIntent)"]`、`a1 -->|"失敗 (3回まで)"| a2`。ラベルの中の `"` は `#quot;` と書く（囲んであれば、かっこ・`:`・`;` はそのまま書ける）。
  - シーケンス図のメッセージと注記では、`;` を `#59;`、`#` を `#35;` と書く（`;` は行の区切りになり、後ろが消えるか構文エラーになる）。
  - ノードの id は英数字にし（`a1`、`pay`）、小文字の `end` を id にしない。日本語はラベルに書く。ラベルの中の改行は `<br/>`。
  - 1つの図は 15 ノードくらいまで。ラベルに文を入れず、長くなる説明は図の下の本文に書く。
- **描いて確かめる。** `layout-check.mjs 文書.md`（`.mmd` でもよい）が、ブロックごとに構文エラーを出し、描いた PNG の場所を出す。GitHub の本文の幅で見るなら `--width 900`。構文エラーを直し、PNG を開いて、文が途中で切れていないか、分かれ道のラベルがあるか、横に広がりすぎて文字が小さくないか（向きを `TD` と `LR` で変える）を見る。mermaid.js は、近くの `node_modules/mermaid` か、無ければ CDN から読む（図の中身は外に送らない。読めないときは、手元に入れる手順が出力に出る）。置く先の Mermaid の版が古いと、新しい書き方が通らないことがあるので、昔からある書き方（`flowchart`・`sequenceDiagram` の基本）で書く。

## PowerPoint のファイル（.pptx）で渡すとき

「PowerPoint で」「あとで自分で直す」と頼まれたら、HTML でなく .pptx を作る。中身の選び方（手順 1）と、描いて見ること（手順 4）は同じで、違うのは次の所。

- **テンプレートに足すときは、テーマを先に読む。** マスターが指すテーマ（多くは `ppt/theme/theme1.xml`）の `a:clrScheme`・`a:fontScheme`、色やフォントを書いた付録のページを読み、テンプレートのレイアウトから作る。色は `a:schemeClr`（python-pptx は `theme_color`・`brightness`）、フォントは名前を書かずテーマに任せる。
- **作り方。** 手元にあるライブラリ（python-pptx、PptxGenJS など）で書く。大きさはテンプレートのまま、無ければ 16:9（13.333×7.5 インチ ＝ 960×540pt）。あとで直せるように、文字は文字の箱、図は図形と線、表は表で作る（図やスライドを1枚の画像にして貼らない）。
- **箱は文字に合わせて広がらない。** PowerPoint の文字の箱は、ライブラリで書いた時点では文字に合わせて広がらない（ライブラリの「自動調整」の指定は、縮める計算をしないものが多いので、あてにしない）。箱の大きさを手順 3 と同じ数え方（全角1字 ＝ 文字の大きさ、半角は半分。単位は pt）で決め、1割ほど余らせる。狭い箱で語の途中（「確／認」）で折り返すときは、箱を広げるか、意味の切れ目で自分で改行する。
- **表は下に伸びる。** セルの文字が折り返すと行が伸びて、スライドの下に出る。列を絞る、言葉を短くする、2枚に分ける。表の文字も、図形の中の文字も、14pt より小さくしない。
- **フォントを名前で書くときは、日本語の側にも入れる。** PowerPoint は日本語を東アジアの側（`a:ea`）のフォントで描く。`a:ea` が無いと日本語はテーマのフォントになり、`a:latin` の名前は英数字にしか効かないことがある。python-pptx の `font.name` は欧文の側にしか入らないので、`a:ea` にも同じ名前を入れる（PptxGenJS の `fontFace` は両方に入る）。フォントは、見る人の PC にあるもの（Windows なら「游ゴシック」「Meiryo」）を選ぶ。
- **確かめる。** `layout-check.mjs deck.pptx` が、Windows に PowerPoint があれば PowerPoint に、無ければ LibreOffice に描かせて、描いた結果の文字の位置から、文字どうしの重なり、塗りのある箱からあふれた文字、スライドの外に出た・切れた文字を pt の座標つきで出す。あわせて中身から、スライドの外に出た部品、小さい文字、`a:ea` の指定もれを出す。まず指摘を、座標を見て直す（当たっている箱を動かす・広げる、文字数を減らす）。指摘が無くなるまで走らせ直す（手順 4 と同じく3回までを目安に）。
- **画像は1回見る。** 検査は、全部のスライドを並べた一覧の画像1枚も作って場所を出す。指摘が無くなったら、一覧を1回開いて、機械で測れない所（図形や線が文字にかかる、語の途中の折り返し、余白の偏り）を見て、気になったスライドだけ1枚ずつの画像を開く。一覧の画像が無いときは、出力にある1枚ずつの画像か PDF を見る。出力に「文字数からの見積もり」とあるときは、指摘は目安なので、描ける手段を探して画像で見る。
- **LibreOffice で描いたときは近似。** フォントと折り返しが PowerPoint と少し違う。出力に「LibreOffice で描いた」とあるときは、返事に「PowerPoint では開いていない」と1文添える。

## 例

頼み：「system.md の構成を構成図にして。architecture.svg で」

やること：部品とつながりを拾う → 左から右へ「利用者 → 入口 → サービス → データ」の列に置き、監視はサービスの枠に1本でつなぐ → 書く → `layout-check.mjs architecture.svg` → 「線が文字を通っている：「書き込み」（x 793, y 365）」→ ラベルを線から上へ離す → 走らせ直して指摘なし → PNG を開いて矢印の向きを見る → 渡す。

返事：「architecture.svg に保存しました。左から右へ注文の流れ、紫の点線が監視です。在庫の照会だけが複製を読みます。」

## 箱が3つほどの簡単な図のとき

聞き返さずに1枚書き、検査を1回走らせて画像を開き、渡す。飾りや説明文を足さない。検査と開いて見ることだけは省かない（簡単な図でも、文字の幅は描かないと分からない）。
