# 根拠（数字と規則の出どころ）

数字と規則は、2026-11-11 に次の原文で確認した。

- [Agent Skills の仕様](https://agentskills.io/specification)：name・description の形、本文の長さの推奨
- [Claude Code の Skills の docs](https://code.claude.com/docs/en/skills)：description を切る位置、一覧の予算、Skill content lifecycle（後のターンで読み直さない、要約のあとに戻す量）、Troubleshooting（`/context` と `/doctor`）、skill-creator
- [Codex の Skills の docs](https://learn.chatgpt.com/docs/build-skills)：一覧の予算と、先に description を短くすること
- Anthropic「The Complete Guide to Building Skills for Claude」（2026-01、PDF）：frontmatter の `<` `>` と name の禁止、Skill のフォルダーに README.md を置かないこと、否定の書き方と「いつ使うか」を聞く修正方法、決まった検査をスクリプトにすること

次の3つは、2026-11-16 に自分で試して確認した。Claude Code に 35〜40本の Skill を入れ、読むかどうかをエージェントに任せて 682回走らせた（作業役のモデルは Sonnet が 654回、Opus が 28回）。公式の docs には見当たらなかった（同じ日に、上の仕様と Claude Code の docs を見た範囲）。ほかのツールでは確認していない。

- Skill が開かれるのは、依頼を受け取ってすぐ：Skill の道具で開かれたのは 433回（Sonnet 414回、Opus 19回）。全部が、依頼を受け取った直後だった（419回は最初の依頼、14回は途中で届いた新しい依頼）。開く前にほかの道具を使った回数は、409回で1回まで、多くても3回。作業を進めたあとの節目（報告の前など）で開かれた回は無い。別に、Skill のファイルを道具を通さず直に読んだ回が 24回あり、うち 6回は作業の途中だった（4回は、集計に入る所で集計の道具の Skill を読んだもの）
- 節目の言い方で書いた description は読まれにくく、依頼の種類で始めると読まれる：修正した3本は、何をする Skill かを先に書き、いつ読むかを後ろに書いていた（「報告する前に読む」「作業の終わりに結果を報告するとき」など）。これを、「〜を頼まれたら、手を付ける前に読む」で始まる形にした。当たる場面で読まれた回は、Sonnet で 15回中1回が 15回、9回中3回が 9回、21回中1回が 10回になった（3本目は、自分の作業のあとに報告文を依頼される場面では、修正しても読まれなかった。6回中0回）。Opus でも同じ向きだった（6回中0回が 6回、4回中4回が 4回、4回中1回が 3回。修正した側には、毎回読む指示に、節目で確認する項目の一覧も追加している）
- 強く書いた Skill は、同じ依頼に当たる道具の Skill を読まれなくする：1回の依頼で読まれる Skill は、多くが1本までだった（661回のうち、0本が 289回、1本が 293回、2本が 71回、3本が 8回）。1本を「手を付ける前に読む」の形に直すと、集計の依頼で集計の道具の Skill が読まれた回が、6回中3回から 12回中0回になった。道具の Skill の description も同じ形に直すと、12回中8回になった

references の指し方は、2026-11-18 に確認した。

- [Claude の Agent Skills のベストプラクティス](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)：本文は 500 行未満、references は1段だけ。同梱のファイルに一度も触れないなら、要らないか本文からの示し方が足りない、と書く。
- 自分で試した数字：Skill を置くだけ（読むかはエージェントに任せる）の試験の記録 2,126 回で、日本語の文章の Skill は 108 回開かれたが、本文で「業務の文書の作法は references/business.md にある」と指していた references は 0 回開かれた。同じ Skill の指し方を「業務の文書では、書き始める前に references/business.md を開く」に変えると、議事録2場面と返信のメール1場面（作業役 Sonnet、各3回）で 0/9 から 9/9 開かれた。点は条件を伏せた採点で議事録 110 → 117/120、メール 21 → 20/24、費用は約 1.5 倍。一方、元の文を残したまま「議事録は、書き始める前にその文書の型の項を読む」と1文を追加した版は、議事録の場面でも 6 回中 1 回しか開かれなかった（点は 116/120 で、この Skill では開かせても誤差の範囲だった）。条件の絞り方と文の置き方のどちらが効いたかは分けていない。確認したのはこの Skill 1本・Sonnet だけで、ほかの Skill・モデル・ツールでは確認していない。それまでの試験は references をプロンプトに入れて測っていて、開かれないことに気付いていなかった。
