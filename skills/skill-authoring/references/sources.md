# 根拠（数字と決まりの出どころ）

数字と決まりは、2026-11-11 に次の原文で確かめた。

- [Agent Skills の仕様](https://agentskills.io/specification)：name・description の形、本文の長さの推奨
- [Claude Code の Skills の docs](https://code.claude.com/docs/en/skills)：description を切る位置、一覧の予算、Skill content lifecycle（後のターンで読み直さない、要約のあとに戻す量）、Troubleshooting（`/context` と `/doctor`）、skill-creator
- [Codex の Skills の docs](https://learn.chatgpt.com/docs/build-skills)：一覧の予算と、先に description を短くすること
- Anthropic「The Complete Guide to Building Skills for Claude」（2026-01、PDF）：frontmatter の `<` `>` と name の禁止、Skill のフォルダーに README.md を置かないこと、否定の書き方と「いつ使うか」を聞く直し方、決まった検査をスクリプトにすること

次の3つは、2026-11-16 に自分で試して確かめた。Claude Code に 35〜40本の Skill を入れ、読むかどうかをエージェントに任せて 682回走らせた（作業役のモデルは Sonnet が 654回、Opus が 28回）。公式の docs には見当たらなかった（同じ日に、上の仕様と Claude Code の docs を見た範囲）。ほかのツールでは確かめていない。

- Skill が開かれるのは、頼みを受け取ってすぐ：Skill の道具で開かれたのは 433回（Sonnet 414回、Opus 19回）。全部が、頼みを受け取った直後だった（419回は最初の頼み、14回は途中で届いた新しい頼み）。開く前にほかの道具を使った回数は、409回で1回まで、多くても3回。作業を進めたあとの節目（報告の前など）で開かれた回は無い。別に、Skill のファイルを道具を通さず直に読んだ回が 24回あり、うち 6回は作業の途中だった（4回は、集計に入る所で集計の道具の Skill を読んだもの）
- 節目の言い方で書いた description は読まれにくく、頼みの種類で始めると読まれる：直した3本は、何をする Skill かを先に書き、いつ読むかを後ろに書いていた（「報告する前に読む」「作業の終わりに結果を報告するとき」など）。これを、「〜を頼まれたら、手を付ける前に読む」で始まる形にした。当たる場面で読まれた回は、Sonnet で 15回中1回が 15回、9回中3回が 9回、21回中1回が 10回になった（3本目は、自分の作業のあとに報告文を頼まれる場面では、直しても読まれなかった。6回中0回）。Opus でも同じ向きだった（6回中0回が 6回、4回中4回が 4回、4回中1回が 3回。直した側には、毎回読む指示に、節目で確かめる項目の一覧も足している）
- 強く書いた Skill は、同じ頼みに当たる道具の Skill を読まれなくする：1回の頼みで読まれる Skill は、多くが1本までだった（661回のうち、0本が 289回、1本が 293回、2本が 71回、3本が 8回）。1本を「手を付ける前に読む」の形に直すと、集計の頼みで集計の道具の Skill が読まれた回が、6回中3回から 12回中0回になった。道具の Skill の description も同じ形に直すと、12回中8回になった
