# Excel で開く CSV

Excel は CSV をダブルクリックで開くと、セルごとに中身を見て数値や日付に読み替える。CSV に `"1-2"` と引用符で書いても止まらない。CSV のファイルをテキストで見ると正しいので、作った側では誤りが見えず、開いた人の画面でだけ値が変わる。開いた人がそのまま上書き保存すると、元の値は戻らない。目的は、開いた人の Excel に、作った値のとおりに見せること。

## 開いたときに変わる値

日本語の Windows の Excel（Microsoft 365）で、引用符で囲んだ CSV を開いて確かめた例（2026-11-16）。

| CSV の値 | Excel の表示 | よく出る列 |
|---|---|---|
| `00123`、`0312345678` | `123`、`312345678` | 顧客コード・社員番号・郵便番号・電話番号 |
| `1-2`、`12-1`、`1－2`（全角のハイフンも） | `1月2日`、`12月1日` | 番地・部屋番号・枝番 |
| `1-2-3`、`3/15`、`1/2` | `2001/2/3`、`3月15日`、`1月2日` | 番地・分数・型番 |
| `2026-11` | `Nov-26` | 年月 |
| `1234567890123456789`（15桁を超える数字） | `1.23E+18`（16桁目から 0 になる） | 口座・カード・伝票の長い番号 |
| `1E5`、`2E-3` | `1.00E+05`、`2.00E-03` | 英数字の型番 |
| `1.10` | `1.1` | 版・規格の番号 |
| `(100)`、`+81` | `-100`、`81` | 括弧つきの番号・国番号 |
| `10:30` | 表示は `10:30` のままだが、値は時刻（0.4375）になり、並べ替えや計算で数として扱われる | 時間帯の文字 |

数字・ハイフン・スラッシュ・コロン・点のほかに、文字が1字でも混じる値は変わらない（`第1-2`、`3-15号`、`No.1-2`）。

## 作るとき

1. **開く人と使い道を決める。**
   - 人が開いて見る・直す（「Excel で開く」「営業や経理の人に渡す」と頼まれた）：この手順に従う。
   - 別のシステムに取り込ませるだけ：値に手を加えず、そのまま書く。3 の `="..."` の形は、取り込むと `="` の字が残る。
   - 両方に使う：2つ作るか、頼んだ人に聞く。
   - 頼みからどれか分からない：値はそのまま書き、Excel で開くと変わる列があれば、返事に1行書く。
2. **Excel に書き換えさせない列（守る列）を、実際の値で決める。** 上の表の形に当たる値が1つでもある列は、その列の値を全部 3 の形で書く。列の名前ではなく、全部の行の値を見る。番地のように、行によって当たったり当たらなかったりする列を見落としやすい。
3. **守り方を選ぶ。**
   - CSV のままなら、守る列の値を `="1-2"` の形で書く。Excel は式として読み、文字の `1-2` を表示する。CSV の欄を引用符で囲むときは、中の引用符を重ねて `"=""1-2"""` と書く（CSV を書くライブラリに `="1-2"` を渡せば、こう書かれる）。
   - 頼んだ人が .xlsx でもよいなら、.xlsx で書き、守る列のセルの書式を文字列にしてから値を入れる。Excel が値を読み替えず、式も残らないので、ほかのシステムにも渡しやすい。CSV を頼まれたときに、聞かずに .xlsx に替えない。
4. **文字コードは、BOM 付きの UTF-8 にする。** BOM はファイルの先頭の3バイト（239 187 191）で、Excel はこれが無い UTF-8 の日本語を化けさせる。渡す先が Shift_JIS を求めるときだけ、Shift_JIS（cp932）にする。
5. **開いて確かめる。** Windows で Excel が入っているなら（下の2行目でエラーにならなければ入っている）、実際に開き、全部の行について、守った列と表の形に当たりそうな列の表示を読み、元の値と同じかを見る。Mac や Excel の無い PC では、全部の値を上の表の形と突き合わせて確かめ、Excel で開いて確かめていないことを返事に書く。

```powershell
# Windows の PowerShell。表示（Text）を全部の行で読む
$x = New-Object -ComObject Excel.Application; $x.Visible = $false; $x.DisplayAlerts = $false
$wb = $x.Workbooks.Open('C:\path\to\list.csv'); $ws = $wb.Worksheets.Item(1)
foreach ($row in $ws.UsedRange.Rows) { ($row.Cells | ForEach-Object { $_.Text }) -join ' | ' }
$wb.Close($false); $x.Quit(); [void][Runtime.InteropServices.Marshal]::ReleaseComObject($x)
```

6. **渡すときに書く。** どの列をどう守ったかと、`="..."` の形はメモ帳やほかのシステムでは式のまま見えることを、返事に書く。

## すでに変わった CSV を直すとき

「Excel で開いたら番地が日付になった」と頼まれたら、Excel で保存し直す前の CSV か、元のデータ（DB・元の表）から、上の手順で作り直す。Excel で上書き保存したあとのファイルは、`1月2日` が `1-2` だったか `1/2` だったかを区別できず、長い番号の16桁目からは失われているので、そこから戻さない。元が無ければ、戻せない列を返事に書く。

## 例

頼み：「顧客.json を CSV にして 顧客一覧.csv で出して。営業の人たちが Excel で開いて使います」（顧客コード `000123`、郵便番号 `0010010`、番地 `1-2`・`3-15`、電話番号 `0312345678`）

- やること：顧客コード・郵便番号・電話番号（先頭の0）と番地（日付になる）を `="..."` で書き、BOM 付きの UTF-8 で保存する。Excel で開き、番地が `1-2` のまま、顧客コードが `000123` のまま見えるのを確かめる。
- 渡す言葉：「顧客コード・郵便番号・電話番号・番地は、Excel が数値や日付に変えないよう `="..."` の形で書きました。Excel で開いて、そのまま表示されるのを確かめています。ほかのシステムに取り込む用には、この形を外した版を作ります。」
