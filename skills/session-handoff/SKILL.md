# 並行するセッションの着手と引き継ぎ

同じリポジトリを、並行して動くエージェント、次の日のセッション、別の PC や別のツールが触る。次のセッションは前の会話を持たない（文脈の要約、クラウドのコンテナの廃棄、別の PC、別のツール）。このため、作業場所はセッションごとに分け、状態はあとから読める所（票と push したブランチ）に置き、そこに「誰が触っているか」も書く。始めるときは、そこから拾う。Anthropic も、長く走るエージェントには進み具合のファイルと git の履歴を残させ、次のセッションの最初にそれを読ませている（「Effective harnesses for long-running agents」）。

git のリポジトリでないフォルダー（文書だけのフォルダーなど）では、git の手順は全部飛ばし、下の「票の道具が無いときの TODO.md」だけを使う。git を入れることはせず、返事にも git の言葉を持ち込まない。

先にリポジトリの指示ファイル（AGENTS.md・CLAUDE.md など）を読む。票の道具（GitHub の Issue、Redmine など）、ブランチの名前、引き継ぎの書き方が定めてあれば、それに従う。票の道具の使い方（API・資格情報）はそちらが持ち、ここには書かない。

## 着手する

1. **並行している作業を見る**：`git status --short --branch`、`git worktree list`、開いている PR（`gh pr list --state open`）。PR を後から作る運用のリポジトリでは、進行中の作業が PR の一覧に出ないので、最近 push された作業ブランチも見る：`git fetch --prune` → `git branch -r --sort=-committerdate --format="%(committerdate:relative) %(refname:short)"`。同じ所を触る作業があれば、その引き継ぎ（下の「拾う」の2）を読んでから始める。
2. **票を探して、後からの書き込みまで読む**：`gh issue view <N> --comments`（GraphQL が使えない環境では `gh api repos/<owner>/<repo>/issues/<N>/comments`）。却下・決着は閉じた票にもあるので、`gh issue list --search "<語>" --state all` でも探す。無ければ、目的と完了条件を書いて起票する。票の道具が無いリポジトリでは、起票の代わりに `TODO.md` に1件足す（「引き継ぎを書く」の「書き先」の3）。
3. **origin/main から worktree を切る**：`git fetch` のあと、本体のチェックアウトでブランチを切り替えない（ほかのセッションが同じフォルダーを使っている）。リモートが無く（`git remote -v` が空）、worktree も作業ブランチもほかに無いリポジトリは、並行する相手がいないので、worktree もブランチも切らずに、本体のチェックアウトでそのまま作業する。切ると、取り込むまで頼んだ人のフォルダーには何も入らない。リモートが無いときは、この手順と「拾う」の、`git fetch`・`gh`・`origin/<ブランチ>` を使う所も飛ばし、手元の `git status`・`git log`・`git worktree list` と `TODO.md` で見る。

   ```
   git worktree add --no-track -b <エージェント名>/<票の番号>-<短い名前> <場所> origin/main   # origin/main を追跡させない
   ```

   ブランチ名に票の番号を入れると、続きを始めるセッションがブランチから票と引き継ぎを探せる。番号は票の番号で、PR の番号ではない（PR はブランチから引く：`gh pr list --head <ブランチ>`）。PR の本文とコミットにも票の番号を書く（`Refs #<N>` など）。
4. **絶対パスで操作する**：シェルの作業フォルダーはコール間で戻ることがあり、相対パスの `git` や `rm` が別のツリーに当たる。`git` を打つ前に `git -C <場所> branch --show-current` で今のツリーを確かめる。
5. **区切りごとに push する**：コミットだけでは、コンテナの廃棄や別の PC への移動で消える。push のたびに CI が走るリポジトリでは、1コミットずつではなく区切りでまとめる。

## 引き継ぎを書く

### いつ書くか

- 作業がセッションをまたぐと分かったとき：続きを残して止める（時間や回数の上限、人の答えを次のセッションで受ける、セッションを閉じる、文脈が要約されそう）、別のエージェントや次のセッションへ渡す。止まったのに書いていない状態で終えない。
- 一度書いた作業は、そのあとの区切り（push したとき）ごとに書き足す。
- 1つのセッションで終わる作業、同じセッションの中で人の返事を待つだけのときは書かない。
- 会話の中で出て、その日にやらない頼み（「今週中に」「後ででいい」「〜さんの返事が来たら」）は、出たその場で書き先に足す。返事の中で「残りは次回」と並べただけでは、次のセッションには何も残らない。

### 書き先

1. リポジトリに定めがあれば、それに従う。
2. 定めが無ければ、作業の PR のコメントに書く。PR がまだ無ければ対応する票のコメントに書く。どちらも無ければ、上の「着手する」の2で起票するか、draft の PR を出してそこに書く（票の道具も PR も使っていないリポジトリは、次の3）。PR を出したら、票の引き継ぎを PR のコメントへ移し、票には移した先を書く。
3. 票の道具も PR も無いリポジトリ（1人で面倒を見ている道具、リモートの無いリポジトリなど）では、リポジトリの直下の `TODO.md` 1つに書く（すでに同じ役目のファイルがあれば、それを使う）。下の「票の道具が無いときの TODO.md」の形にする。
4. 票の道具に届かない場所で作業しているとき（社内の票に家から届かない、など）は、作業ブランチにコミットしたメモ（定めが無ければ `HANDOFF.md`）に書き、届く場所で票へ移す。メモはマージの前に消す。
5. 任された子のエージェントで、push・PR・票への書き込みを任されていないときは、引き継ぎを報告に書いて返し、親が書き先に置く。

書いたら、作業ブランチを push してから止める。push 先が無ければ、コミットしてから止め、作業がどのブランチ・どのフォルダーにあるかを、止めるときの返事に書く。会話、コミットしていないファイル、エージェントのメモリだけに置かない。メモリはほかのツールとほかの PC から読めない。

公開のリポジトリでは、票・PR・コミット・push したファイル（引き継ぎのメモを含む）のどれにも、社外に出せない事情を書かない。マージの前に消しても、push した時点で履歴に残る。そうした事情は、届く場所の非公開の票にだけ書く。

### 何を書くか

一番新しい引き継ぎが、そのまま従える1つになるように書く。票や PR のコメントは書き換えずに毎回新しく足し、冒頭にどれを置き換えたか（日時か、リンク）を書く。書き換えると、同じアカウントで書いたほかのコメント（人の答えなど）を上書きしかねず、並びも書いた順でなくなる。ブランチのメモは、その1つを書き換える。

- **いまの状態**：ブランチと、push した HEAD の SHA（メモに書くときは、メモのコミットの直前の SHA）、何ができていて、どの検査がどの結果だったか（コマンドと終了コード）。
- **残り**：やる順に、どのファイルのどこか、何で確かめれば済みか。何回ものセッションにまたがる仕事は、最初に残りを全部この一覧に未完で書き、1つずつ進めて、確かめてから済みにする。
- **その場で下した判断**：理由と、外れていたときの影響。
- **気をつける所**：測り直す値、実機が要る所、止まりやすい所、確かめていない所。
- **待っているもの**：人の答え、レビュー、ほかの PR のマージ。
- **作業中か、手放したか**：まだ自分が続けるなら「作業中」と、どの PC・どのツールのセッションかを書く。手放すなら「手放した」と書き、決まっていれば次に触る人を書く。手放したあとは自分では直さず、気づいたことはコメントにする。同じ場所を2つのセッションで直すと、どの判断が誰のものか追えなくなる。

### 票の道具が無いときの TODO.md

やることの一覧と引き継ぎを、この1つで兼ねる。票の道具の代わりなので、マージの前に消さず、残し続ける。

```
# やること

印：[ ] まだ ／ [~] 途中・待ち ／ [x] 済み

1. [x] 夜勤の翌日に早番を入れたら警告を出す
   - 終わり：validate が違反を返す試験が通る。README の「決まり」の表に1行足す。
2. [~] 休業日にシフトが入っていたら警告を出す
   - 終わり：実物の休業日の CSV で check を走らせて、違反が出るのを見る。
   - 途中：判定と試験は済み。CSV は総務の佐藤さんが 11/20 に送る。届いたら列の並びを見て読み込みを足す。
3. [ ] 月間の集計（店舗ごとの合計時間）を出す ― 11/25 の会議で見せる
   - 終わり：`summary` のコマンドで店舗ごとの合計が出る。
```

- **1行に1件、やることを動詞で書き、下に「終わり」（終わったと言える状態）を1行付ける。** 終わりは、試験が通る・このコマンドでこれが出る、のように確かめられる形にする。期限と、ほかの項目が前提になることは、その行に書く。
- **済みにするのは、「終わり」を全部確かめてから。** 一覧に載せる前から実物で済みと確かめられた頼みは、根拠を書いて済みにする（聞くことに回さない）。人やデータを待って終えられないものは「途中・待ち」にして、できた所・残り・誰の何をいつまで待つかを書く。
- **何をするかが決まっていない頼み（「スマホで見たい」「使いやすく」）は、作業にせず、「誰に何を聞く」の1件にする。** 聞いても作業にならないものは載せない。
- **軽く保つ。** 項目ごとの長いメモ、日程表、優先度の段、ラベルは足さない。順番は並びで表す。1人で読み返して保てる長さ（1件に2〜3行）を超えたら、削る。
- 待ちの項目があっても、ほかの項目は手元の材料で進める（去年の版を土台に案を作る、など）。聞くことは案と一緒に出す。
- 作業のたびに、終えたときと止めるときにこのファイルを直し、git のリポジトリなら作業と同じコミットに入れる。始めるときは、このファイルと git の履歴・コードを読み、食い違えば実物を正としてファイルを直す（人が手で済ませて、印を直していないことがある）。

## 拾う（続きから始める）

1. **最新を取る**：`git fetch`。手元にその作業の worktree があれば、`git -C <場所> log --oneline HEAD..origin/<ブランチ>` でリモートが先に進んでいないかを見る。無ければ、票や PR からブランチを知る（どちらにも届かなければ、「着手する」の1の、最近 push されたブランチから探す）。
2. **引き継ぎを探して読む**：リポジトリの `TODO.md`、`origin/<ブランチ>` のメモ（`git show origin/<ブランチ>:HANDOFF.md` など）、ブランチ名の番号の票、ブランチから引いた PR。一番新しい引き継ぎと、そのあとのコメントまで読む。引き継ぎのあとに決着や訂正が書かれていることがある。
3. **触ってよいかを見る**：引き継ぎが「作業中」で、そのセッションが自分でないとき、または worktree にコミットしていない変更があるとき（`git -C <場所> status --short`）は、ほかのセッションが使っているかもしれない。その worktree には触らず、人に確かめる。人がこの作業の続きを頼んだのなら、「手放した」引き継ぎは確かめずに拾ってよい。
4. **作業場所をそろえる**：worktree があれば `git -C <場所> merge --ff-only origin/<ブランチ>` で進める（進められないなら、手元にだけあるコミットがある。止めて人に確かめる）。無ければ `git worktree add <場所> <ブランチ>` で切る（ローカルに同じ名前のブランチが無ければ、`origin/<ブランチ>` を追うブランチができる。`origin/<ブランチ>` をそのまま渡すと、ブランチの無い detached HEAD になる）。切ったあとも `git -C <場所> merge --ff-only origin/<ブランチ>` を走らせる（前に残した古いローカルブランチがあると、それで切られる。進められなければ、上と同じく止めて確かめる）。
5. **引き継ぎの HEAD と今の HEAD を比べる**：違えば、その間のコミットを読む（メモだけを変えたコミットは除く）。ほかのセッションが進めている。
6. **検査を一度走らせる**：書かれた状態と合うかを確かめてから進める。合わなければ実物を正とし、引き継ぎを直す。
7. 届く場所でメモを見つけたら、中身を票へ移し、ブランチからは消す。

## 片付ける

- 消す前に、worktree に未コミットの変更が無いこと、PR がマージ済みか、ほかの PR の土台になっていないこと、引き継ぎが「作業中」で別のセッションのものでないことを確かめる。
- `git worktree remove <場所>` → `git branch -D <ブランチ>` → リモートに残っていれば `git push origin --delete <ブランチ>`。
- 別のツリーで実行して作った一時ファイルは、作ったツリーと実行したツリーの両方で消す。
- 本体のチェックアウトの main は `git merge --ff-only origin/main` で進める（未追跡のファイルは残る）。
- squash でマージしたあと、元のブランチの上で作業を続けない。続きは origin/main から切り直すか、まだマージしていないコミットがあれば `git rebase --onto origin/main <元の土台>` で載せ替える（push 済みなら force push が要るので、人に確かめてから）。
- 票は、完了条件を満たしたかを見てから閉じる。`Refs` でつないだ票は自動で閉じない。公開などの作業が残る票はマージだけで閉じない。
