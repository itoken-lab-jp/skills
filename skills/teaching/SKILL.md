# 人に教える

教えるとは、相手が自分でできるようになるまでを手伝うこと。AI に教えさせると、相手を知らないまま種類を全部並べた長い講義をし、相手に手を動かしてもらわずに終わりやすい。何日かに分けると、前の回の内容を残さないので、次の回は「昨日の内容を教えてください」から始まる。

一言で答えれば済む質問（「A と B の違いを一言で」）には、一言で答える。この手順は、相手が身につけたいときのもの。

## 1. 目的と今の知識をつかむ

- 作業のフォルダーに相手の資料やデータがあれば、教える前に開いて中身を見る。問題も確かめも、そのデータでする（相手に貼ってもらうのは、読めないときだけ）。
- 何に使いたいか（毎月の報告を自分で作りたい、試験に受かりたい）と、今どこまで分かるか（似たものを知っているか）を、1〜2問で聞く。頼みや手元の資料で分かれば聞かない。
- 教える中身と例は、目的に合わせて選ぶ。相手の仕事の形（帳票・データ・場面）で教えると、覚えたことをそのまま使える。
- 相手がすでに知っているものにたとえる（Excel の関数を知っている人に、プログラムの関数を教える、など）。
- 相手が使う道具と版に合わせる（社内で使う DB、相手の OS、相手のエディタ）。例も問題も、その道具の書き方で出す。手元に同じ道具が無いときは、別の道具で確かめたことを言い、相手の道具で試してもらう。

## 2. 1回に1つを短く

- 1回で教えるのは、目的に要るいちばん手前の1つにする。種類を全部並べない。ほかの種類は、要る場面が来てから教える。
- 説明は短くし、すぐ手を動かしてもらう。説明を聞いて分かった気になることと、自分でできることは違う。

## 3. 小さな問題を出し、答えに返す

- 目的に近い小さな問題を、相手の手元のデータ（なければ小さな例）で出す。答えは相手に書いてもらう。
- つまずきやすい所（月末をまたぐ日付の計算で1日ずれる、空の値が集計から黙って抜ける、など）は、説明で先に言うより、問題で踏んでもらう。データを見せて「件数と合計は合っていますか」と確かめさせると、自分で気付ける。
- 答えには、合っている所と違う所を、返事の中で具体的に返す（どの入力で・どう違うか、なぜか、どう直すか）。記録のファイルに書くだけでは相手に届かない。直した答えをもう一度書いてもらうと身につく。
- 自分で気付いてもらう問いは1回までにする。それで気付けなければ、次の返事で答えと直し方を示す。問いを重ねて相手を待たせない。
- 直し方を示すときは、手元のデータの全部の形（全角・空の値・書き方の揺れなど）で通るかを確かめてから示す。
- 相手が「これで合っていますよね？」と聞いたら、うなずく前に、結果を一緒に確かめる。

## 4. 次の一歩と出どころ

- 終わりに、次にやることを1つ示す（目的に向かう次の1歩）。長い課程表は出さない。
- 続きを自分で読める先（公式の docs など）を1つ示す。細かい書き方や版による違いは、記憶で言い切らず、docs で確かめてから言う。

## 5. 何回かに分けて教えるとき

AI は次の会話で前の回を覚えていないことがある。記録は作業のフォルダーに残す。

- 回の終わりに、学びの記録（例：`学びの記録.md`）に書き足す。目的、今回できるようになったこと、つまずいた所（どんな答えを書き、何が違ったか）、次にやること。相手が読んでも分かる言葉で書く。
- 次の回は、記録を読んでから始める。前の回の要点は、説明し直すより、短い問いで思い出してもらう（「前回つまずいた〇〇は、どう書けば防げますか？」）。答えられたら次に進み、詰まったら少し戻る。
- 記録が見つからなければ、前の回に何をしたかを相手に1問だけ聞いて、そこから始める。
