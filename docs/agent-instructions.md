# agent-instructions

AI エージェントは、AGENTS.md・CLAUDE.md・`.cursor/rules` のような指示ファイルを毎回読み込んでから働きます。指示ファイルは、使ううちに長くなり、書いてあるコマンドやパスが古くなり、ツールごとのファイルの間で中身が食い違っていきます。読ませる量が増えるほど1行ごとの効き目は下がり、「書いてあるのに守られない」が起きます。agent-instructions は、指示ファイルを新しいリポジトリに置くとき、足すとき、見直すときの手順です。

## 使い方

Claude Code・Codex など、Skill の共通の形式（[Agent Skills](https://agentskills.io/specification)。フォルダーに手順書の `SKILL.md` を置く形）を読むエージェントで使えます。どのツールの指示ファイルにも使えるよう、ツールに寄せずに書いています。ツールごとの置き場や上限の大きさはよく変わるので、Skill は書く前に公式の docs で確かめさせます。

入れておくと、エージェントは次の頼みで読み込みます。

- 「新しいリポジトリにエージェントの足場を作って」
- 「CLAUDE.md が長くなって守られてない気がする。見直して」
- 「AGENTS.md と GEMINI.md と Copilot の instructions があって、どれが効いてるのか分からない」

確実に読ませたいときは「agent-instructions の Skill に従って」と名前で頼んでください。

## Skill を入れずに頼むと

下の「試した結果」の2つの場面で、Skill を入れない AI は、正本を1つにする、無いコマンドやパスを直す、事故から生まれた決まりを残す、といった中身の整理はよくできました。外したのは次の2つです（各3回）。

- 測らない：見直しで毎回読み込まれる量を数えず、どれだけ減ったかを示さなかったのが3回中2回。
- 確かめ方を言わない：直した指示が新しいセッションで本当に読み込まれるかの確かめ方を、6回とも伝えませんでした。今のセッションは起動したときの指示のまま動くことが多いので、直した本人の会話では効いたかが分かりません。

新しいリポジトリの足場では、Skill なしでも3回とも、短い AGENTS.md と `@AGENTS.md` だけの CLAUDE.md を作りました。

## SKILL.md に書いてあること

AI が読むファイルです。どう動くかを確かめたいときは [SKILL.md](../skills/agent-instructions/SKILL.md) を開いてください。

- 3つの原則：毎回読ませるのはコードを読んでも分からないことだけ（1行ごとに「消したら間違えるか」で決める）。同じ決まりは1つのファイル（正本）にだけ書き、ほかのファイルからは正本を指す。書いてあることは実物と照らす。読ませる量が減り、ファイルの間でずれなくなります。
- 置く：複数のツールが読むファイル（AGENTS.md）を正本にし、ツール専用のファイルは正本を取り込むか指すだけにします（例：Claude Code の CLAUDE.md に、AGENTS.md を取り込む `@AGENTS.md` の1行だけを書く）。書くこと（推測できないコマンド、落とし穴、戻せない操作の扱い）と書かないこと（コードから分かること、言語の一般的な作法、ファイルごとの説明、経緯）。完了の前に走らせる検査を1つ決めます。main ブランチへの直接の push を止める設定や必須の CI は、エージェントが作れないことが多いので、人に頼む項目として挙げます。
- 足す：同じ説明か同じ失敗が2回起きたときに足します。毎回は要らない手順は Skill に、毎回必ず起きてほしいこと（編集後の整形、危ない操作を止める）は、ツールが決まった時に自動で走らせるスクリプト（フック）や CI に置きます。事故から生まれた決まり（例：本番の DB に直接マイグレーションを流して列を消したので、先に staging で確かめる）は、理由と一緒に書きます。
- 見直す：読み込まれる量を測る → コマンド・パス・仕組みの主張を実物と照らす → 重複とツールの間の食い違いを片づける → 古いモデル向けの書き方（大文字の IMPORTANT、「必ず再確認しろ」、古いモデルの不具合を理由にした決まり）を外す → 事故から生まれた決まりは残す → 経緯やファイルの説明を外に出す、の順です。
- 確かめる：新しいセッションで、読み込まれた指示を見せるコマンドか、指示ファイルにしか書いていないことを聞いて確かめます。

## 試した結果

2026年11月に、架空のリポジトリ2つで試しました。作業する AI（Claude の Sonnet。Claude Code を道具つきでリポジトリの写しの中で動かす）に頼みごとをし、頼んだ人の役は別の AI（Sonnet）が演じました。会話・操作の記録と最後の差分を、Skill の有無を伏せて別の AI（Claude の Opus）が採点しました。場面ごとに守ってほしいこと（観点）を決め、それぞれを満たしたかを見ました。場面は Skill を書く前に作りましたが、この Skill は Skill なしの結果を見たあとに書いています。Skill の中の例は場面と違う題材にしています。

表の数字は、満たした観点の数を3回分足したもので、分母は観点の数（場面1は9、場面2は7）×3回です。一部だけ満たした観点は数えていません。

| 場面 | Skill なし | Skill あり |
|---|---|---|
| 1. 長くなった CLAUDE.md を見直す（無いコマンドとパス、AGENTS.md との重複、`.cursor/rules` との食い違い、古いモデル向けの書き方、事故から生まれた決まり、経緯の節） | 20/27 | 27/27 |
| 2. 新しいリポジトリに足場を置く（秘密の実データのフォルダー、絞り込みの要る試験のコマンド） | 12/21 | 18/21 |

- 読み込まれる量を測って前後を示したのは、Skill なし3回中0回（一部だけ1回）、Skill あり3回中3回でした。
- 新しいセッションで読み込まれるかの確かめ方を伝えたのは、場面1と2を合わせて、Skill なし6回中0回、Skill あり6回中4回（一部だけ1回）でした。
- 場面2の Skill ありでは、頼まれていない設定ファイル（pyproject.toml）に1行足したことが3回中1回ありました。報告はしていましたが、頼まれた範囲の外なので、採点では範囲を越えたと数えました。
