# talk-slides

AI エージェント（Claude Code や Codex のように、ファイルを読み書きして作業を進める AI）に「メモから 10 分の発表を作って」と依頼すると、見た目の整ったスライドと原稿が返ってきます。ところが、原稿を声に出すと 5 分で終わり、聞き手に一番関係のある話は最後のページにあり、書き手の部署の略語がそのまま出てきます。AI は、メモに書いてある順のまま作り、書いた原稿の字数を数えないからです。

talk-slides は、人前で話す発表のスライドと原稿を AI に作らせるときの、AI が読む手順書（Skill）です。聞き手に持ち帰ってほしいことを1つに決め、聞き手が自分の話だと思える所を前半に置き、持ち時間から原稿の字数を決めて数え、見出しを主張の1文にして、話す文はスライドのノート（発表者だけが見る欄）と原稿に置かせます。スライドは、会議で映したあと資料だけで読まれることを基本に、図の横に、話す文とは別の短い文（根拠、条件、「ただし〜」の但し書き）を残させます。スライドは PowerPoint のファイル（.pptx）などで出てきます。効くのは、10 分前後の、原稿まで要る発表です。1 枚の報告や短い修正では、追加しても結果はほとんど変わりません（下の「試した結果」）。会議・報告会・勉強会の発表を AI に手伝わせる人に向いています。

## 使い方

Claude Code・Codex など、Skill の共通の形式（[Agent Skills](https://agentskills.io/specification)。フォルダーに手順書の `SKILL.md` を置く形）を読むエージェントで使えます。入れ方は [README](../README.md) のコマンド（`npx skills add itoken-lab-jp/skills -g --skill talk-slides`）です。入れておくと、エージェントは `SKILL.md` の先頭にある説明文（どんなときに読むか）を見て、次のような依頼のときに自分で読み込む作りです（ほかの Skill と並べて置いたときに、実際に読み込まれるかは、まだ試していません。読まれないときは「talk-slides を読んで」と依頼します）。

- 「memo.md をもとに、来週の月例会で 10 分話す発表を作って。スライドと原稿を」
- 「上司に文字が多いと言われた。話しやすいように直して」
- 「ストーリーを組み直したい」

図の文字の重なりやはみ出しを修正する手順は入っていません。そちらは、別の Skill の [figure-making](figure-making.md)（作ったスライドを画像にして、重なりやはみ出しを測って修正させる）が受け持ちます。一緒に入れるのを勧めます。

## 何をさせるか

入れておけば、下のことは AI が手順書を読んで自分で行います。依頼の文に書き足す必要はありません（大きな会場で映すだけ、配って読ませるだけ、のときは、依頼にそう書きます）。

- **スライドがどう見られるかを先に決める。** 基本は「会議で映して話し、あとで資料だけでも読まれる」です。この形では、文字を大きく少なくしすぎず、1枚に 200〜300 字、本文 16pt（16:9 の標準の大きさで、スライドの高さの約 3%）を基準にします。数百人の会場で映すだけなら文字を減らして大きくし、配って読ませるだけなら本文を 12〜14pt まで下げて文を増やします。AI に任せると、どの場面でも文字が大きくて少ないスライドになりやすいので、依頼の言葉で分けさせます。
- **色・文字の大きさの段・ページの骨組みを、1枚目を作る前に決める。** 色は主の色と強調の色の2つ、文字の大きさは4段ほど（隣の段は約 1.25 倍）、見出しと図の位置はどのページでも同じにします。大きくするのは、見せたい数字だけです。
- **持ち時間から量を決めて、数える。** 話す速さを1分に約 300 字として、画面を見せる間を引き、10 分なら 2,500〜3,000 字。書いたあとに字数を数えさせます。
- **見出しは主張の1文、図と数字はその証拠、話す文はノートと原稿、図の横には根拠・条件・但し書きの文。** 主張の見出しと図の型（assertion-evidence）は、名前の見出しと箇条書きの型より、聞いた人の理解が良かったという比較の研究があります（Garner & Alley, 2013）。話す文とそっくり同じ文を画面に出すと理解が落ち、短い要約なら助ける、という研究もあります（Yue, Bjork & Bjork, 2013）。画面に残すのは、話す文の写しではなく、あとで読む人が結論と根拠をたどるための短い文です。出どころは、Skill に同梱の [references/sources.md](../skills/talk-slides/references/sources.md) にまとめています。
- **渡す前に、AI が見出しだけを1枚目から順に読んで、話が通るかを確認する。** スライドだけを読んだ人が、同じ結論と根拠にたどり着けるかも見させます。
- **強調は1枚に1か所。**
- **箱の角の丸み・余白・行間は、使う値を数通りに決めてそろえる**（余白は 8・16・24pt のどれか、など）。ばらばらだと、なんとなく雑に見えるためです。

## 試した結果

下の点数は、スライドの文字の量と大きさの基準を今の形（資料だけでも読まれる前提）に直す前の版で取ったものです。修正したあとの版は、10 分の発表を2回作らせて、文字の大きさがそのときの基準の段にそろうこと、図の横に根拠の文が付くこと、文字の重なりとはみ出しが無いことを目と検査で見ただけで、点は取り直していません。文字の大きさと量の基準は、公開されている上場時の説明資料 12 枚を測り、同じページを本文 12・14・16・18pt で作って見比べて決めた目安で、読みやすさを比較した実験によるものではありません。

2026-11-27 に、架空の題材 4 つで、Claude Code（モデルは Sonnet）に依頼しました。どちらの条件にも figure-making を読ませ、talk-slides を追加するかどうかだけを変えています。採点は、条件を知らせない別のモデル（Opus）が、作られたスライドの画像と記録を見て行いました。点は、場面ごとに 5〜13 個の観点（10 分の発表 13、修正 11、1 枚の進捗 5、配る資料 9）（聞き手に関係のある話が最初の 3 枚以内にあるか、原稿が持ち時間に合う字数か、数字が元のメモと合うか、など）を、満たした 1 点・一部 0.5 点・満たさない 0 点で付け、2〜3 回ぶんを足したものです。1つのモデル、場面ごとに 2〜3 回の試しで、傾向を見るためのものです。人の目での採点とは照らしていません。

| 場面（修正する前の版での点） | talk-slides なし | あり |
|---|---|---|
| メモから 10 分の発表（スライドと原稿） | 30/39 | 37/39 |
| 文字の多い 6 枚を、5 分で話す用に直す | 28/33 | 30/33 |
| 1 枚の進捗（罠のない小さな依頼） | 10/10 | 10/10 |
| 配って読ませる 3 枚の資料（話さない） | 24/27 | 25/27 |

差が出たのは、10 分の発表だけでした。ほかの 3 場面の 1〜2 点の差は、回ごとの振れと区別できません。1 枚の進捗は、追加しても遅くならない・余計なことをしないことの確認です（ほかの場面でも、入れて点が下がったものはありませんでした）。

- 原稿の字数：なしは 3 回とも 1,300〜1,600 字（1分 300 字で数えると約 5 分）。ありは 3 回とも約 2,600 字。
- 聞き手の入口：なしは 3 回のうち 2 回、聞き手に関係のある話が後半か最後。ありは 3 回とも最初の 3 枚以内。
- 聞き手の知らない言葉：なしは 3 回とも一部が説明なしで残り、ありでも 3 回のうち 2 回は一部が残りました（残った言葉は、人が読んで修正します）。

見出しを主張の1文にすること、話す中身をノートに置くことは、figure-making だけでもほぼできていました。つまり、talk-slides が追加するのは、話の順と量（聞き手の入口、持ち時間に合う字数、言葉の説明）です。SKILL.md の色と余白をそろえる節は、効くかどうかを試していません（もとは、実際の発表を作りながら人が気付いた所です）。AI が作り終えるまでの時間は、10 分の発表で平均 約 1.5 分から約 2.7 分に増えました（各 3 回）。1 枚の進捗では、AI からの聞き返しも、依頼していない原稿も増えませんでした。

## 入れ方

```
npx skills add itoken-lab-jp/skills -g --skill talk-slides
```

`-g` は、プロジェクトごとではなく、自分のユーザーのどのプロジェクトでも使える場所に入れる指定です。手順の本文は [SKILL.md](../skills/talk-slides/SKILL.md) です。入れ方の詳しい説明（置かれる場所、ツールごとの違い）は [README](../README.md#入れ方) にあります。

- 2026-11-28：手順の順を「原稿 → 設計表 → スライド → 全ページを並べて照合して直す」に組み直した。1枚目を作る前に、テンプレートの欄の位置・色の役割・芯の図・ページごとの主張と図の型を設計表に書き（ひな形は references/color-and-boxes.md）、作ったあとは一覧の画像で色ごと・主張・空き・文の形を数えて、まとめて直す。本文は重なりを削って短くした（本文の高さに対する文字の比、主の色を言い切りの帯に使うことは本文から外した）。figure-making との食い違い（映すスライドの文字の下限）は、発表のスライドではこちらを先にした。
- 2026-11-28：見出しに主張を書くか話題を書くかを、見出しの欄の大きさで決める形にそろえた（2行入るなら主張、細い1行なら話題で主張は下の一文）。図の下の根拠・条件・留保は述語まで書く。字数が足りないときに資料に無い事例を作らない、字数はスライドの印を除いて文字単位で数える、既存のスライドの修正ではレイアウトの欄を動かさない、「原稿は要らない」と言われたら書かない、形式の指定が無ければ .pptx、配って読ませるだけの資料では入口の順と返事の字数も使わない、を追加した。文字の段の数の目安（4つほど）を外した。
