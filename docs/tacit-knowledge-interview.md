# tacit-knowledge-interview

仕事のやり方のうち、判断の基準・例外・失敗から学んだこと・コツは、やっている本人の頭の中にしかないことが多く、本人は「普通にやっているだけ」と思っています。tacit-knowledge-interview（暗黙知の聞き取り）は、AI が聞き手になって本人とチャットで何往復も話し、それを引き出して、後任が読んで同じように動ける手順書にする手順です。異動や退職の引き継ぎ、属人化した仕事の手順書づくり、自分の仕事を AI に任せたいときに使います。

## 使い方

エージェントに「〇〇さんの〇〇のやり方を聞き取って、後任向けの手順書にして」「自分の見積書づくりを Skill にしたいので、聞き取りをして」のように頼みます。エージェントは、読み手・聞く時間（例：30分、12往復）・手元の資料を確かめてから、1回に1つずつ問いを出します。

- 本人が自分で答えるときは、そのままチャットで返事を書きます。
- 別の人（退職する人など）から聞くときは、頼んだ人が AI の問いを本人に伝え、本人の返事を要約せずにそのまま貼ります。要約すると、言いかけてやめた話や遠回しな言い方が消えるためです。

終わると、次の2つが手元に残ります。

- 手順書：仕事の段ごとに「やること・判断の基準と数（理由）・例外と対処・誰が決めるか」と、聞けなかった所の一覧。頼めば、AI が読んで同じ仕事をする Skill（SKILL.md）の形で書きます。
- 頼んだ人あてのメモ：まだ聞けていないこと、本人以外に確かめが要ること、本人が約束した資料と期限。

最後に下書きを本人に読んでもらい、違う所を直します。

## AI に何も渡さずに聞き手をさせると

次の所で取りこぼします。この Skill はそこを受け持ちます。

- 1回の発言に問いを3つ4つ並べる。人は最初の1つにしか答えず、残りは消える。
- 1つの話を深く掘り続け、仕事のほかの部分の締め切りや、誰の許可が要るか、例外を聞かずに時間が終わる。
- 画面の操作やファイルの場所など、資料を見れば分かることに時間を使う。
- 「あと証明書の……いや、いいです」のように本人が言いかけてやめた話に戻らない。
- 「毎日」「必ず」を、月末のような例外の日で確かめない。上司の「いつでも連絡して」（実際は「朝まで待てるものは朝に」）や、取引先の「確認しておきます」を字面のまま書く。
- 下書きを本人に読ませない。本人の「〜と思う」を、決まった手順に書き上げる。

## 中身

どれも AI が聞き取りの中で読むファイルで、使う人が読む必要はありません。

- `SKILL.md`：聞き取りの間ずっと守ること（1回に問いは1つ、まだ聞いていないことを AI の手元のメモ（控え）に積んで戻る、1つの話は3往復まで、本人の言葉と聞き手の推測を分ける）と、準備から本人の読み合わせまでの8つの手順。聞く時間の半分を使ったら、仕事全体に5つの問い（何時までならそのままやるか、自分では決めずに許可を取ることは何か、いつものやり方が通じない時期はあるか、相手から返事が来ないときはどうするか、言われたとおりにやってはいけない頼みはあるか）を1つずつ聞きます。
- `references/probes.md`：場面ごとの問いの例。熟練者の判断を聞き出す研究の手法（Klein らの Critical Decision Method、Militello と Hutton の Applied Cognitive Task Analysis）と、AI が聞き手になるインタビューの研究（Geiecke と Jaravel）の問いを、日本の職場で通じる言い方に直しました。
- `references/japanese-cues.md`：日本語の会話で字面と意味がずれる言い方（謙遜、「毎日」「全部」のような言い切り、「〜ようにはしてます」のような弱め、言いかけてやめる話、他人の「確認しておきます」、上司の「いつでも連絡して」）の読み方と、確かめる問い。
- `references/output.md`：手順書・SKILL.md・メモの形。

## 試した結果

2026年11月に、架空の2つの仕事（夜間バッチが失敗したときの一次対応、見積書の作成）で試しました。聞き手と話し手を、別々のサブエージェント（会話の中から立てる別の AI。Claude の Sonnet を使用）にしました。話し手は架空の担当者を演じ、聞かれたときだけ話す事実を7〜8個持っています。12往復までの聞き取りで、聞き手が引き出せた事実の数を数えました。1回の発言に問いが2つ以上あると、話し手は最初の1つにだけ答えます。

表の「初版」「改版」「第3版」は Skill の版で、版ごとに1回ずつ試しました。公開している版は、第3版のあとに、試していない小さな直し（1文に問いを2つ入れる形も2問と数える、締めの問いを残り3往復に早める、上司の「いつでも連絡して」の読み方を足す、問いの例を1問ずつに割る）を入れたものです。

| | Skill なし | Skill あり |
|---|---|---|
| 夜間バッチ（事実 8） | 1。上司の「いつでも連絡して」を字面のまま書いた | 初版 3（ほかに 1 は、聞いたが答えが返らず未確認）、第3版 4 |
| 見積書（事実 7） | 2（ほかに 1 は一部だけ） | 初版 3、改版 4（どちらも、ほかに 1 は一部だけ） |
| 問いを2つ以上並べた発言 | 夜間バッチ 9回、見積書 10回（各11往復） | 5回の試行で 0〜3回（各11〜12往復） |

Skill の初版は、1つの話に長く留まり、締め切りや許可を聞かずに終わりました。そこで「1つの話は3往復まで」と「半分を使ったら5つの問いを聞く」を足しました。夜間バッチで試し直すと、「再実行は朝6時まで」「本番の DB を手で直すときは開発の課長の承認を残す」「ディスクは80%で対応するが、月末だけは90%まで待つ」が出ました。下書きを話し手に読ませた回では、聞き手が強めて書いた所（本人は「そういう感じでやると思う」と言ったのに「決まった手順」と書いた）を本人が直しました。

どれも各1回の試行で、採点はこの Skill の作者がしています。数字は目安です。言いかけてやめる話は、初回の試行で話し手が一度も口にせず、聞き手が試せませんでした。そのため、見積書の改版と夜間バッチの第3版の回だけ、言いかけてやめる話と言い切り（「その日のうちに出します」など）を、話し手に決まった往復までに言わせています。この2回の数字には、それをきっかけに取れた事実が1〜2つ入っています。
