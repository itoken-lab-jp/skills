# 目的を預かる（指示ファイルに書き足して使う）

AI エージェント（Claude Code や Codex のように、ファイルを読み書きして作業を進める AI）に大きな目標を相談すると、依頼していないのに目標を小さくして返してくることがあります。「記帳の作業をゼロ時間にしたい。馬鹿みたいな目標なのは分かっている」と依頼しても、最初の返事は「完全なゼロは現実的ではありません。9割の削減を目標にしましょう」になります。言っていることは正しいのですが、難しいことは依頼した側も承知しています。欲しいのは、その目標のままどう攻めるかの案で、それが返ってきません。

下の「本文」は、この癖を直す約350字の文です。AI が毎回読む指示ファイル（Claude Code の `CLAUDE.md`、Codex などの `AGENTS.md`）に入れて使います。入れると、AI は次のように動きます。

- 大きな目標は、そのままの目標として受け取る。難しさは理由を付けて一度だけ言い、あとは「何が成り立てば届くか」と「最初に試すこと」を出す。
- 試したことがうまくいかなかったときや、案に欠点を見つけたときは、目標ごと否定せず、その方法の問題として扱う。使える部分、うまくいく条件、次に安く試せることも一緒に返す。
- その代わり、試した結果がうまくいったかどうかの判定は甘くしない。たとえば「この数字を超えたら成功」と先に決めた基準を、結果を見てから下げない。

バグの修正や決まった実装のように、やることが決まっている作業の依頼には、何も追加しません。

目標に付き合うことと、判定を甘くしないことを1つの文にまとめたのは、片方だけだと、何でも「いいですね」と言う AI になるためです。

このページは、AI エージェント向けの手順書（Skill）を公開しているリポジトリ itoken-lab-jp/skills の一部です。この文は Skill ではないので、Skill を1本も入れていなくても、これだけを入れて使えます。

## 使い方

入れ方は2つあります。

- **手で貼る。** 下の「本文」の枠の中を、指示ファイルにそのまま貼ります。どの仕事でも効かせたいなら、全体の指示ファイル（Claude Code なら `~/.claude/CLAUDE.md`、Codex なら `~/.codex/AGENTS.md`）に貼ります。特定のリポジトリの仕事だけで効かせたいなら、そのリポジトリの指示ファイルに貼ります。迷ったら全体の方です。
- **エージェントに依頼する。** このリポジトリの Skill [agent-instructions](agent-instructions.md) を入れている人向けです。「itoken-lab-jp/skills の rules/holding-the-goal.md を、全体の指示ファイルに入れて」と依頼します。エージェントは、本文の前後に「どこから持ってきた文か」と日付を書いたコメント（`<!-- 出どころ: itoken-lab-jp/skills/rules/holding-the-goal.md 2026-11-20 ここから -->` のような行）を付けて入れます。あとで本文が新しくなったときは「更新して」と依頼すれば、そのコメントに挟まれた部分だけが置き換わります。

どちらも、入れたあとの新しい会話から効きます。[rules/holding-the-goal.md](../rules/holding-the-goal.md) は、下の枠の中と同じ文だけを置いたファイルです。

効いているかを見るには、大きすぎる目標を1つ、入れる前と後の新しい会話で相談して、最初の返事を比較します。入れる前は目標を小さく言い換えていた返事が、入れた後は目標をそのままにして攻め方を出していれば、効いています。

## 本文

AI に向けて書いた文なので、言葉が詰まっています。貼るだけなら読まなくても使えます。読む場合の言葉の意味は次のとおりです。

- 「預かる」：目標を、評価したり言い換えたりせずに、決まったものとして受け取ること。
- 「試し」：案がうまくいくかを確認する、1回の実験や検証。
- 「試した方法に付け」：うまくいかなかった原因を、目標ではなく、そのとき使った方法の側に置くこと。
- 「線」：何を満たせば成功と言うかの基準。「数え方」は、結果の数字の出し方です（たとえば、10通り試して一番良かった1つを見せるなら、10通り試したことも一緒に数える）。
- 「閉じる条件」：どうなったらその進め方をやめるかを、先に決めたもの（例：「同じ考えで3回うまくいかなければやめる」）。
- 「筋」：同じ考えから出した試しのまとまり。「閉じた筋は生かし直さず」は、やめると決めた進め方を、少し手直しして続けないことです。
- 「見立て」：なぜうまくいくはずか、という考え。
- 「この項目の返し」：この文に従って AI が返事に追加するもの（使える部分、うまくいく条件、次に試すこと）。

```markdown
# 目的を預かる（厳しさは判定に向ける）

ユーザーが承知で選んだ大きい目標・無茶に見える目標は、そのまま預かる。依頼されずに縮めない・置き換えない・先送りしない。見込みの低さは理由つきで一度だけ言い、あとはその目標が成り立つ条件と最初の試しを本気で詰める。外れた結果や欠点は試した方法に付け、残ったもの・どの条件なら生きるか・一番安い次の試しを同じ重さで返す。厳しさは判定に向ける——効いたと言う線、数え方、欠点の重さ、ユーザーが先に決めた閉じる条件は、結果を見たあとに押されても、こちらからは動かさない（閉じた筋は生かし直さず、次は別の見立てから出す）。ユーザーが線そのものを決め直すと明示したら、済んだ結果には当て直せないことを一度言って従う。依頼が作業だけ（集計・変換・修正）なら、この項目の返し（残ったもの・生きる条件・次の試し）は付けない。
```

## Skill にしていない理由

Skill を使っている人向けの説明です。使っていない人は飛ばして構いません。

Skill は、エージェントが依頼を受け取ったときに、説明文を見て読むかどうかを決める手順書です。この文が扱うのは手順ではなく、どの依頼にも関わる構えです。大きな目標の相談は、企画・調査・レビューなど、どんな依頼の形でも来ます。依頼の種類で選ばれる Skill では拾いきれないので、毎回読まれる指示ファイルに置きます。

## 試した結果

2026年11月20日に、Claude Code で試しました。相談の場面を4つ作り、場面ごとに3回、AI に返事をさせました。返事をするモデルは Sonnet です。場面ごとに「最初の返事で目標を置き換えなかった」のような観点を6〜8個決めておき、観点ごとに 0〜2 点を付けました。4場面・3回ぶんの満点は 162 点です。採点は、この文を入れた回かどうかを伏せて、別のモデル（Opus）にさせました。

場面は次の4つです。

- 趣味の自動売買の研究で、試した6つの売買ルールが全部うまくいかなかった人が、今後どうするかの意見を求める
- 自分の企画を「厳しめにレビューして」と依頼する
- 「記帳をゼロ時間に」という大きすぎる目標の攻め方を相談する
- 惜しい結果を見た本人が「成功の基準を下げてもう1回やりたい」と押してくる（断るのが正解の場面）

| AI に読ませたもの | 取れた点 |
|---|---|
| 作者がふだん使っている全体の指示ファイルと Skill 約40本（この文は無い） | 130 |
| 上に加えて、この文を全体の指示ファイルの中の1項目として入れる | 144 |
| 上に加えて、この文を指示ファイルの外で、独立した指示として読ませる | 152 |

指示ファイルに貼って使う場合に近いのは、2行目の 144 です。3行目は、試験の道具で、指示ファイルとは別の指示としてこの文だけを渡した値で、ふだんの使い方では再現しにくい形です。長い指示ファイルの中に埋もれると効きが少し落ちる、という目安として載せています。3行目は少し前の版の文（終わりの2文が今より短い）で測りました。

- 大きすぎる目標の場面では、この文が無い条件（表の1行目のほか、何も入れない、指示ファイルだけを入れる、の3通りで計9回）のうち8回が、最初の返事で目標を置き換えました。この文を入れた条件（文の版を変えて計12回）では、11回が目標をそのまま受け、1回は「例外だけ人が見る形ならほぼゼロ」と範囲を少し緩めました。
- 成功の基準を下げたい、という依頼は、この文があっても無くても、全部の回で断りました。この文を追加しても、何でも聞き入れる AI にはなりませんでした。
- 表を1つ作るだけの依頼では、この文を入れても、余計な助言を追加しませんでした。

## 分かっていないこと

- 場面は作者と AI が書いたもので、各3回です。144 と 152 のような小さい差は、たまたまかもしれません。
- 「厳しめにレビューして」と依頼した場面では、指示ファイルの1項目として入れても、ほとんど変わりませんでした（42点満点で 31 → 32）。指摘を12個ほど並べ、企画の良い所は後回しでした。厳しいレビューを依頼するときは、「良い所と、どうすれば成り立つかも同じ重さで」と依頼に書き足す方が確かです。
- 「同じ考えで3回うまくいかなければやめる」と先に決めてあった進め方を、新しいデータでもう1回試そうとする回が、3回のうち1〜2回残りました。
- Claude Code 以外（Codex など）では試していないので、同じように効くかは分かりません。
