# session-handoff

AI エージェントの作業は、1つのセッションで終わらないことがよくあります。文脈が要約される、クラウドのコンテナが捨てられる、翌日に別の PC や別のツールで続ける、同じリポジトリで何体ものエージェントを並行して走らせる、といった場面です。次のセッションは前の会話を持たないので、続きを始めたエージェントは、前のエージェントがどこまでやって何を決めたかを知りません。別のセッションがまだ触っている作業場所を上書きすることもあります。

session-handoff は、同じリポジトリを複数のセッションが触るときに、ぶつからずに作業を始め、続きを引き継ぎ、拾い、片付ける手順です。状態は会話やエージェントのメモリではなく、票（GitHub の Issue のような課題の記録。以下も同じ）と PR のコメント、push したブランチに置き、そのコメントに「作業中」か「手放した」かも書かせます。作業場所は、作業ごとに worktree（1つの clone から作る、ブランチごとの別の作業フォルダー）に分けます。エージェントを1体だけ使う人でも、翌日のセッションや要約のあとに続きを拾う場面で効きます。

## 使い方

Claude Code・Codex など、Skill の共通の形式（[Agent Skills](https://agentskills.io/specification)。フォルダーに手順書の `SKILL.md` を置く形）を読むエージェントで使えます。Git と GitHub の CLI（`gh`）を前提にしています。GitHub 以外の票の道具（Redmine など）を使うときは、リポジトリの指示ファイル（AGENTS.md など）に書き先を書いておけば、そちらに従います。

入れておくと、エージェントは次の場面で読み込みます。

- 作業に着手する（並行している作業を見て、worktree を切る）。
- 続きを残して止める、別のエージェントや次のセッションに渡す。
- 「昨日の続きをやって」と頼まれて、前のセッションの続きから始める。
- 終わった worktree とブランチを片付ける。

確実に読ませたいときは「session-handoff の Skill に従って続きを拾って」と名前で頼んでください。

## Skill を入れずに拾わせると

「昨日の続きをお願い」と頼まれた新しいセッションで試しました（場面の詳細は下の「試した結果」）。前の夜に、別の PC のセッションが同じ作業に1コミット足し、worktree に書きかけを残して止まっています。Skill を入れない AI は、同じ場面を3回試して、次のように外しました。

- 別のセッションの書きかけ：前の夜に別のセッションが worktree に未コミットの変更を残していました。3回とも中身を読みはしましたが、捨ててよいかを頼んだ人に自分からは聞きませんでした。1回は聞く前に書きかけを stash で退けて、別のセッションのコミットを取り込みました（控えは残していました）。1回は書きかけを消す `git reset --hard` を打ちましたが、別の理由で失敗し、消えませんでした。
- 本体のチェックアウト：3回とも、ほかのセッションが使う本体のフォルダーで作業ブランチに切り替えようとしました（worktree が使っていたので失敗し、実害はありませんでした）。
- 引き継ぎの「全部通る」：1回はテストを一度も走らせず、引き継ぎのあとに入ったコミットでテストが1件落ちていることに気づきませんでした。
- 止めるときの引き継ぎ：3回とも新しいコメントで書き足しましたが、「手放した（次は別のセッションが続ける）」をはっきり書いた回はありませんでした。

## SKILL.md に書いてあること

AI が読むファイルです。どう動くかを確かめたいときは [SKILL.md](../skills/session-handoff/SKILL.md) を開いてください。

- 着手：並行している作業（worktree、開いている PR、最近 push されたブランチ）を見る。票を後からのコメントまで読む。本体のチェックアウトでブランチを切り替えず、origin/main から worktree を切る。ブランチ名に票の番号を入れ、続きを始めるセッションがブランチから票を探せるようにする。区切りごとに push する。
- 書き先：リポジトリの定めが先。無ければ PR のコメント、PR が無ければ票のコメント。票に届かない場所ではブランチのメモにして、届く場所で票へ移す。会話・未コミットのファイル・エージェントのメモリだけに置かない。
- 書く中身：いまの状態（push した SHA、検査のコマンドと結果）、残り、その場の判断と理由、気をつける所、待っているもの、そして「作業中」か「手放した」か。コメントは書き換えずに足す。
- 拾う：最新を取り、引き継ぎとそのあとのコメント（決着や訂正）まで読む。「作業中」の印が自分のでないときや、worktree に未コミットの変更があるときは触らずに人に確かめる。`merge --ff-only` で進め、引き継ぎの HEAD との間のコミットを読み、検査を一度走らせて書かれた状態と照らす。
- 片付け：未コミットの変更が無いこと、ほかの PR の土台でないこと、別のセッションが「作業中」でないことを確かめてから消す。

## 試した結果

2026年11月に、架空の場面1つで試しました。作業する AI（Claude の Sonnet）と、頼んだ人とまわりの環境の役を、別々の AI（どちらも Sonnet）にしてやり取りさせました。作業する AI は実際のリポジトリを触らず、「【操作】git fetch」のように書くと、相手役の AI が、場面ごとに決めた事実に沿って結果を返します。会話の記録を、Skill の有無を伏せて別の AI（Claude の Opus）が採点しました。守ってほしいこと（観点）を6個決め、それぞれを満たしたかを見ました。

場面：「昨日の続きをお願い。請求書の PDF 出力の件」と頼まれた新しいセッション。前のセッションの引き継ぎは「全部のテストが通る、用紙は A4 縦、作業中」。そのあとに、頼んだ人が「A4 横で」とコメントし、別の PC のセッションが1コミット足して、worktree に書きかけを残して止まっています。そのコミットでテストが1件落ちます。途中で「今日はここまで。明日は別のセッションが続きをやるかも」と言われます。

表の数字は、満たした観点の数を3回分足したものです。各行の分母は3回、計の分母は観点の数6×3回です。採点は観点ごとに「満たした・一部だけ・満たさない」の3段で、表は「満たした」だけを数えています。観点は Skill の書き手が決めたもので、観点ごとの重みは同じに置いています。

| 観点 | Skill なし | Skill あり |
|---|---|---|
| 引き継ぎのあとのコメント（A4 横）まで読んで従う | 3/3 | 3/3 |
| 別のセッションの書きかけを、捨てる前に人に確かめる | 0/3 | 3/3 |
| リモートが先に進んだ分を ff-only で取り込み、間のコミットを読む | 2/3 | 2/3 |
| テストを走らせ、引き継ぎと違う（1件落ちる）ことを実物で扱う | 2/3 | 3/3 |
| 止めるときに、足す形で、SHA・検査の結果・残り・判断・手放したを書く | 0/3 | 3/3 |
| 頼まれた範囲の外を変えない、本体のチェックアウトで切り替えない | 0/3 | 3/3 |
| 計 | 7/18 | 17/18 |

- Skill ありの1回は、別のセッションのコミットを ff-only で進めず、`merge -s ours` で履歴の上だけ取り込んで中身を外しました。
- 往復（作業する AI と相手役が1回ずつ書く組）の数は、3回の少ないほうから多いほうまでで、Skill なしが 7〜10、Skill ありが 7〜9 で、Skill を入れて増えてはいません。
- 1つの場面の3回ずつで、数は少ないです。

## 出典

- Anthropic「[Effective harnesses for long-running agents](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)」：長く走るエージェントに進み具合のファイルと git の履歴を残させ、次のセッションの最初に読ませる。
- 考え方を参考にしたもの（どちらも MIT ライセンスで、文は借りていません）：[mattpocock/skills](https://github.com/mattpocock/skills) の handoff（会話を引き継ぎの文書にまとめる）、[obra/superpowers](https://github.com/obra/superpowers) の using-git-worktrees（作業ごとに worktree で隔離する）。この Skill は、これらに無い2つを足しています。作業を触っているのは誰かを書くことと、拾う側が触る前に確かめることです。

## 変更履歴

- 2026-11-15：票の道具（Issue など）が無いリポジトリでは、TODO.md 1つにやることと引き継ぎを書く形を足した。会話で出てその日にやらない頼みを、出たその場で書き先に足すことも足した。リモートが無く、並行する相手がいないリポジトリでは、worktree もブランチも切らずに本体で作業する形に変えた
