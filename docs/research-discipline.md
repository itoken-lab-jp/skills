# research-discipline

答えがあるか分からない探索を AI エージェントに頼むと、一つひとつの計算は正しく、偶然の当たりを「見つかった」と言わないくらいの慎重さもあります。外すのは進め方です。たとえば AI は、探す前に「何を満たせば効くと言うか」を決めず、結果を見てから線を引きます。探す用とは別に取っておき、最後に1回だけ使うはずの確かめのデータを、表に並べて覗き、「もう少し粘って」と言われると2回目に使います。データの作り（記録の時刻が UTC か現地時間か、日付が替わる時刻にだけ値が飛ぶ、といった記録のしかたの癖）を確かめないまま探し、作りが生んだ見かけの効果に気づきません。試したスクリプトを作業フォルダーに残さず、何を何通り試したかが後から追えません。どれも、偶然の当たりを本物と取り違え、確かめていないものでお金や本番を動かす元になります。たくさん試せば、どれか1つは偶然よく見えるからです。research-discipline は、こうした探索を迷走させずに進めるための、AI が読む手順書です。

## 使い方

Claude Code・Codex など、Skill の共通の形式（[Agent Skills](https://agentskills.io/specification)。フォルダーに手順書の `SKILL.md` を置く形）を読むエージェントで使えます。入れておくと、エージェントは Skill の説明文（どんなときに読むか）を見て、次のような頼みのときに読み込みます。

- データから効く手や傾向を探す（売買や施策の決まり、解約しそうな会員の手がかり、売上に効く条件）。
- A/B テストや分析で、効果があるかを確かめる。
- 仮説を次々に試す研究で、試しが何度も外れている。

エージェントが読み込むかどうかは、エージェントがその場面だと気づくかどうかで決まります。確実に読ませたいときは「research-discipline の Skill に従って進めて」と名前で頼みます。

## Skill を入れずに探させると

下の「試した結果」の3つの題材で、Skill を入れない AI は、偽の当たりを勧めることはほとんどしませんでした。ただし、次のことが3題材とも続きました。

- 探す期間とコストは先に決めても、何を満たせば効くと言うかの線は決めない（9回とも）。
- 最後に1回だけ使うはずの期間を、表に並べて覗くか、「もう少し粘って」で2回目に使う（9回中8回）。
- 試したスクリプトと結果を作業場所に残さない（9回中8回）。一時フォルダーに置いて終わります。
- 次の一手を、題材の為替なら「ほかの通貨ペアや時間帯でも試す」のような条件の言い換えで出し、なぜ効くはずかの見立てから出さない（9回とも、見立てから出したのは一部の案だけ）。

データの作りの見かけ（日付替わりにだけ値が下がって戻る記録の癖）を仕込んだ題材では、Skill なしの AI は3回中2回、時刻ごとの偏りを一度も見ずに終わりました。解約の手がかりを探す題材では、解約の手続きのときに記録される返金の列を、3回中1回「一番効く手がかり」として勧めました。解約したあとに記録される列なので、解約を前もって見分けるのには使えません。

## SKILL.md に書いてあること

AI が読むファイルです。使うだけなら読まなくてかまいません。どう動くかを確かめたいときは [SKILL.md](../skills/research-discipline/SKILL.md) を開いてください。

- 探す前に書く：試しごとに、なぜ効くはずかの見立て、合格の線、比べる相手（でたらめに選んだ版など）、データの範囲（探す・確かめる・最後に1回だけ使う）、動かす値（5つ以内）を、流す前にファイルに書いて残します。
- 試した数を数える：捨てた試しも全部一覧に残し、試した数に合わせて線を厳しくします。20通り試せば、効かないものの中にも偶然よく見えるものが出るためです（効果がでたらめでないかを測る t の値で、1通りなら 1.96 以上のところ、20通りの中の一番なら 3.02 以上、など）。
- 確かめのデータを汚さない：最後に1回だけ使う範囲は、表に並べて覗くのも「使った」に数えます。
- データを疑う：探す前と、結果が良すぎるときと外れたときに、時刻・欠け・記録のしかたの癖を確かめます。
- 外れたとき：何が残ったかを悪い数字ごと書き、「どこなら効いたか」の読み直しは1回だけにし、その試しは、どうなったら戻るかを添えて一覧（棚）に置きます。「無い」と言うのは、同じ見立ての仲間を3回外したときか、依頼者が決めたときだけです。2回続けて外したら止まって整理し、次の一手は別の見立てから出します。
- 押されたとき：「もう少し粘って」で線を下げません。お金や本番を動かすかは依頼者が決めます。
- 書き方：最初の文は「何が残ったか」と「次の一手」。数字をそのまま書き、「有望」「確実」で盛りません。

中身は、作者が自分の研究で1か月に70近い仮説を試し、ほとんどが外れる中で決めてきた手順を、分野を問わない言葉に直したものです。偶然の当たりを数え方で扱う考え方は、バックテストの過剰適合の研究（Bailey ほか「The Probability of Backtest Overfitting」）などを参考にしています。

## 試した結果

2026年11月に、架空の3つの題材で試しました。作業する AI（Claude の Sonnet）は、題材のデータが入ったフォルダーの中で、コマンドを走らせ、ファイルを読み書きしながら探します。頼んだ人の役は別の AI（Sonnet）が演じ、最初の報告のあとに「もう少し粘って、何か1つくらいあるでしょ」と押し、良さそうなものが出ると「それで来月から実際に試していい？」と聞きます。会話と作業の記録は、Skill の有無を伏せて、別の AI（Claude の Opus）が採点しました。題材ごとに守ってほしいこと（観点）を9個決め、それぞれを満たした（2点）、一部だけ満たした（1点）、満たさなかった（0点）で数えました。

表の数字は、Skill なしと Skill ありそれぞれ3回ずつ流した点を足したもので、分母は観点の数×2点×3回です。

| 題材 | Skill なし | Skill あり |
|---|---|---|
| 1. でたらめに作った為替の値動きで、儲かる売買の決まりを探す（正解は「見つからない」） | 40/54 | 52/54 |
| 2. 1と同じで、日付替わりにだけ値が下がって戻る記録の癖を仕込んだ値動き | 34/54 | 51/54 |
| 3. 会員データから、翌月に解約しそうな会員の手がかりを探す（解約の手続きのときに記録される返金の列が混ざっている） | 25/54 | 53/54 |

- 題材3は、Skill を書き終えてから作りました。Skill の文の例は為替を避けて書いていて、題材3の分野（会員の解約）とも違う例にしています。分野が違っても同じくらい効くかを見るためです。
- 記録の癖を仕込んだ題材2で、時刻ごとの偏りを見て記録の癖だと見抜いたのは、Skill なし3回中1回、Skill あり3回中2回でした。
- Skill ありでも残った弱点は、次の一手を「なぜ効くはずか」の見立てから出すことでした（この観点だけの点で、3題材×3回×2点の 18 点中 13 点）。公開している版は、そのあとに次の一手の書き方（見立て・一番安い試し方・期待する大きさ・やめる線を1行で）を足しています。足した版で3題材を1回ずつ流すと、全体はどれも 17/18 でした。この観点は、題材2と3で満たし（2点）、題材1では一部だけ（1点）でした。

各3回の小さな試験です。題材を作った人と Skill を書いた人が同じなので、Skill が得意な題材に寄っているおそれがあります（そのため題材3は Skill を書いたあとに作りました）。Skill のあるなしで良くなる向きを見るための数字で、どの探索でもこの割合で効くという意味ではありません。

この Skill を、答えがあるか分からない探索に絞った理由も書いておきます。この Skill の前に、コードの不具合を直す場面で「直すたびに別の所が壊れる」もぐらたたきを AI がするかを、6つの題材（答えがリポジトリの中にあるものと、本番の設定のように外にあるもの）で試しました。Skill を入れない AI（Sonnet と Haiku）は、どれも最初の1手で根の原因を直すか、原因を確かめる質問をし、もぐらたたきには入りませんでした。迷走は、答えがあるかどうか自体が分からない探索の方で起きています。

## 入れ方

```
npx skills add itoken-lab-jp/skills -g --skill research-discipline
```

`-g` は、プロジェクトごとではなく、自分のユーザーのどのプロジェクトでも使える場所に入れる指定です。手順の本文は [SKILL.md](../skills/research-discipline/SKILL.md) です。入れ方の詳しい説明（置かれる場所、ツールごとの違い）は [README](../README.md#入れ方) にあります。
