# windows-script-encoding

AI エージェントに Windows のバッチファイル（.bat）や PowerShell のスクリプト（.ps1）を書かせると、日本語のフォルダー名やメッセージを含むものが、別の PC やタスクスケジューラーで動かしたときに文字化けして止まることがあります。原因はファイルの文字コードです。Windows に最初から入っている cmd（.bat を動かすもの）と Windows PowerShell 5.1（.ps1 を右クリックで実行したときに動くもの）は、ファイルの先頭に BOM（「このファイルは UTF-8 です」という3バイトの印）が無いと、日本語を Shift_JIS として読みます。AI がファイルを書く道具は BOM の無い UTF-8 で書くので、そこで食い違います。AI が自分で試す PowerShell は新しい 7 のことが多く、7 は BOM が無くても正しく読むので、AI が試して動いても、渡した先で壊れます。

windows-script-encoding は、スクリプトをどのプログラムで動かすかに合わせて文字コードを選ばせ、そのプログラムで確かめさせる、AI が読む手順書です。日本語を含む .bat・.ps1 を AI に作らせて、ほかの PC や社内の人、タスクスケジューラーで動かす人に向いています。

## 使い方

Claude Code・Codex など、Skill の共通の形式（[Agent Skills](https://agentskills.io/specification)。フォルダーに手順書の `SKILL.md` を置く形）を読むエージェントで使えます。入れ方は [README](../README.md) のコマンド（`npx skills add itoken-lab-jp/skills -g --skill windows-script-encoding`）です。入れておくと、エージェントは Skill の説明文（どんなときに読むか）を見て、次のような頼みのときに自分で読み込みます。

- 「毎朝タスクスケジューラーで走らせる backup.bat を作って」
- 「社内の PC に配る、PATH を足す PowerShell のスクリプトを作って」
- 「この .ps1 を右クリックで実行したら文字化けして止まった。直して」

下の試しでは、スクリプトを書く頼みの 12 回すべてで読み込まれました。エージェントやモデルによって読み込まないことがあるので、確実にしたいときは「windows-script-encoding の Skill に従って」と名前で頼みます。

## 試した結果

2026-11-16 に、作者の日本語の Windows 11（PowerShell 7.6 と Windows PowerShell 5.1 が入っている）で、Claude Code の Sonnet に頼みました。1つの環境、1つのモデルでの試しです。AI が作ったスクリプトは、作者が cmd と 5.1 で動かし直して、動くかを確かめました。

まず Skill なしで、Windows で AI がつまずきそうな 11 の場面（PowerShell と bash の書き分け、空白や `[ ]` を含むファイル名、改行コード、実行ポリシー、PATH の追加など）を、場面ごとに 3 回（配る .ps1 だけ 6 回）、計 36 回頼みました。つまずいたのは文字コードの2つの場面だけでした。

- 日本語のフォルダー名を含む backup.bat：6 回とも UTF-8 で書いた。AI が自分で動かして確かめた 3 回は、エラーを3〜4回出してから直した。「いまは作るだけでいい」と頼んで動かさなかった 3 回は、壊れたまま渡した。1件もコピーされないうえ、うち2回は失敗しても成功の印（終了コード 0）を返すので、タスクスケジューラーでは成功に見える。
- 社内に配る .ps1（PowerShell の版の指定なし、動かさずに渡す）：6 回のうち 3 回が日本語を BOM なしで書き、5.1 で読み込めなかった。なお、頼みに「5.1」や「配る PC で動かす」と書いた別の3つの場面では、9 回とも正しく書いた。

次に Skill ありで、同じ場面を 3 回ずつ頼みました。秒は AI が作業を終えるまでの時間です。

| 場面 | Skill なし | Skill あり |
|---|---|---|
| backup.bat を作るだけ（動かさない） | 3 回中 0 回動く | 3 回中 3 回動く |
| backup.bat を作って動かして確かめる | 3 回とも最後は動く。途中でエラー3〜4回、53〜72 秒 | 3 回とも動く。エラー 0 回、27〜32 秒 |
| 配る .ps1 を作るだけ（動かさない） | 6 回中 3 回動く | 3 回中 3 回動く |
| 日本語入りの .ps1（5.1 と明記、動かす） | 3 回とも動く（24〜28 秒） | 3 回とも動く（28〜37 秒。BOM を付けて確かめる分、少し長い） |
| 罠の無い頼み（.txt の行数を数える） | 7〜10 秒 | Skill は読み込まれず、8〜10 秒 |

最後の行は、関係の無い頼みで Skill が邪魔をしないかを見るためのものです。Skill ありの .bat は、日本語の処理を BOM 付きの .ps1 に置き、.bat はそれを呼ぶだけの英数字の1行にする形で書きました。

## SKILL.md に書いてあること

AI が読むファイルです。使うだけなら読まなくてかまいません。どう動くかを確かめたいときは [SKILL.md](../skills/windows-script-encoding/SKILL.md) を開いてください。

- どのプログラムで動かすかを先に決めます。PowerShell 7 だけと言われなければ、.ps1 は 5.1 でも読めるように書きます。
- 日本語が要らなければ英数字だけで書きます。.ps1 に日本語を入れるなら BOM 付きの UTF-8 で保存します。
- 日本語を含む .bat は、処理を BOM 付きの .ps1 に置いて .bat を呼び出すだけにするか、動かす PC の文字コード（日本語の Windows なら Shift_JIS）で保存します。cmd の文字コードを UTF-8 に切り替える `chcp 65001` は、行がずれて壊れるので使いません。
- BOM は Windows で動かすファイルにだけ付けます。Linux・Mac で動かす .sh に付けると、1行目の `#!/bin/bash` が読まれず止まります。
- 書いたら、`powershell.exe`（5.1）や `cmd.exe` で動かすか、少なくとも読み込めるかを確かめます。確かめられなかったときは、渡すときの返事にそう書きます。
