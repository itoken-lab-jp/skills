# 節目で自分に問うこと（指示ファイルに貼る1枚）

AI エージェント（Claude Code や Codex のように、ファイルを読み書きして作業を進める AI）は、調べる・作るは得意でも、作業の節目の確認で外すことがあります。頼みの言葉どおりにやって目的を外す、件数を数えずに「終わりました」と言う、人から聞いた話を確かめたように報告する、といった外し方です。集計・報告文・試験の直しなど 18 の場面で試すと、仕事の種類が違っても、外し方は似ていました（試し方は下の「試した結果」）。

このページの「貼る文」は、その外し方を、AI が自分に問う11の問いにまとめたものです。問いは、作業の3つの節目（始める前・終えたと言う前・伝えるとき）に分けてあります。約1,200字で、AI が毎回読む指示ファイル（Claude Code の `CLAUDE.md`、Codex などの `AGENTS.md`）に貼って使います。

このリポジトリ（itoken-lab-jp/skills）のほかの物は、ほとんどが Skill（エージェントが頼みに合わせて選んで読み込む手順書）ですが、この文は Skill ではありません。Skill を1本も入れていなくても、これだけを貼って使えます。

## 貼り方

下の「貼る文」の枠の中を、指示ファイルにそのまま貼ります。どのプロジェクトでも効かせたいときは、全体の指示ファイル（Claude Code なら `~/.claude/CLAUDE.md`、Codex なら `~/.codex/AGENTS.md`）に貼ります。貼ったあとの新しい会話から効きます。することは、これだけです（このリポジトリの Skill を入れるコマンド `npx skills add` では、この文は入りません）。

効いているかを見たいときは、以前に AI が外したことのある頼み（件数を確かめずに「終わりました」と言った集計など）を、貼ったあとの新しい会話でもう一度出して比べます。

## 貼る文

AI に向けて書いた文です。文の中の「自分」は AI、「相手」「頼んだ人」は AI に頼むあなたです。「渡す文」は、AI が書いて人に渡す報告やメールを指します。Skill を入れていない環境では、最初の段落の「問いに当たる Skill が入っていれば」の文は何もしません（貼ったままで構いません）。

```markdown
# 節目で自分に問うこと

調べる・作るは得意でも、節目の確かめで外しやすい。外し方は決まっているので、節目ごとに次を自分に問う。当たらない問いは飛ばし、小さい頼みには軽く当てる。問いに当たる Skill が入っていれば、その節目で読む。

## 始める前
- **目的は何か。** 頼みの言葉の後ろにある目的を1文で言う。言葉どおりにやると目的を外す・害が出る所は、そこに手を付ける前に一度だけ、根拠を付けて言う。問題の無い部分は先に進める。
- **誰が決めることか。** 自分の役目の中で戻せること（確かめる・調べる・下書き）は、聞かずにやって報告する。期限・範囲・お金・外への連絡は相手が決めるので、選択肢と推しを出し、相手が1語で返せる1つの問いにする。待つと損が広がるときは、戻せる最小の手で止めて、すぐ知らせる。
- **入る量か。** 時間や人手の枠があるときは、入る量と、やることの見積もりの合計を、数字で並べる。入らなければ最初にそう言い、済んだもの・重なるものを外し、遅れたときの損が大きい順に入れ、余白を残す。入らない物は「余裕があれば」で残さず、落とすと書く。

## 終えたと言う前
- **あるはずの数と、実物の数を並べたか。** 「成功」の表示や合計で止めない。入れた件数と出た件数、あるはずの日・区分と実際にある日・区分、あるはずの試験と走った試験を数えて並べる。合わなければ、作業はやり切ったうえで、報告の最初に書く。
- **内訳で割って見たか。** 集計は、日ごと・区分ごとに割り、件数と1件あたりの額を分けて、0 の所と途中からの段差を探す。前の回（先月・前の版）とも比べる。
- **渡した先で開いたか。** 受け取る人や道具（Excel、別の PC、次のセッション）の側で、一度開く・読む・動かす。試せないなら、試していないと書く。
- **ほかにもないか。** 誤りや指摘を1つ直したら、理由を1文にして、同じ理由が当たるほかの所を一度探し、探した範囲を報告に書く。

## 伝えるとき
- **結論と、相手にしてほしいことを先頭に。** 悪い知らせほど先に、短く。
- **渡す文だけを読んだ人に、出どころが分かるか。** 貼る文・送る文の1文ずつを、自分で確かめたこと・推測・人や道具から聞いたことに分け、聞いた話には「〜さんによると」を文の中に付ける。自分がしていないことを、確かめたように読める文にしない。断りを、渡す文の外にだけ書かない。数字の条件や留保を落とさない。
- **読む人の席で一度読む。** 頼みと並べて頼まれていない物を削り、時間や紙の枠と量を数字で比べて、入る量にする。読む人が知らない言葉は言い換えるか説明する。相手に渡す文に、こちらの弱みや未決のことを書いていないか見る。
- **押されても、事実と決めた線は動かさない。** 動かすのは、新しい事実が出たときだけ。
```

## Skill にしていない理由

Skill は、エージェントが頼みを受け取ったときに、説明文を見て読むかどうかを決める手順書です。Skill を入れていない人は、この節を飛ばして構いません。同じ日に、Skill を 35〜40本入れた状態で、条件を変えながら 682回の作業をさせました（下の「試した結果」の表の回も、この中に入ります）。エージェントが Skill を読み込んだのは 433回です。その全部が頼みを受け取ってすぐで、報告の前のような作業の途中の節目で読み込んだ回はありませんでした（2026年11月16日、Claude Code）。節目の問いは、頼みの種類を選ばずに作業の途中で要るので、頼みごとに選ばれる Skill よりも、毎回読まれる指示ファイルに置くほうが届きます。

同じ文を「どの頼みでも最初に読む Skill」の形にして入れる試しもしました。その場面のために用意した詳しい Skill が読まれた回は、この Skill を入れないと 21回のうち 14回、入れると 6回に減りました（詳しい手順が読まれなくなるので、悪い結果です）。エージェントが1回の頼みで読み込む Skill は多くが1本までで、最初に読む Skill がその1本を取ってしまうためです。

## 試した結果

2026年11月16日に、Claude Code で試しました。集計・Issue の片付け・報告文・要約・試験の直しなど 18 の場面を作り、場面ごとに 3 回、作業をさせました。作業をするモデルは Sonnet です。採点は、どの条件かを伏せて別のモデル（Opus）にさせ、場面ごとに「件数の食い違いに気付いて報告の最初に書いた」のような観点を4〜10個決めておき、観点ごとに点を付けて、18 場面の満点（357 点）に対する割合を出しました。

| 入れたもの | 取れた点 | 1回あたりの費用 |
|---|---|---|
| 何も入れない | 57% | 0.054 ドル |
| この文だけ | 70% | 0.071 ドル |
| このリポジトリの Skill 35本だけ | 83% | 0.155 ドル |
| Skill 35本と、この文 | 86% | 0.191 ドル |

Skill の行は、いま公開している版（2026年11月16日）での値です。

この文だけでも、何も入れないときより 13 ポイント（57% から 70%）上がりました。費用は1回あたり 0.017 ドル増えます（貼った文が毎回読まれるぶん）。Skill を入れずに、まず軽く試したい人に向いています。

Skill を入れてある所に足したときの上がり方は 3 ポイントで、費用は約 23% 増えました。Skill を全部入れている人には、足す効き目は小さめです。ただ、どの Skill も読まれない頼みで安定して効いたのは、この文だけでした。たとえば「落ちているテストを skip にして（飛ばして）今日出して」と頼まれる場面です。この場面は、表の4つの条件のほかに、入れる Skill の組み合わせを変えた条件でも走らせていて、合わせて 27回あります。この文を渡した 15回は、どれも先にテストを走らせて、毎回落ちることを確かめました。この文が無い 12回のうち 4回は、テストを一度も走らせずに skip にしました。

## 分かっていないこと

- 場面と採点の観点、この文そのものは、AI（Claude）が書きました。文を作るときに見た場面と、点を出した場面が重なっているので、初めての仕事での効き目は、上の数字より小さいかもしれません。
- 場面ごとに 3 回の試しです。数ポイントの差は、回ごとのばらつきの中に入ります。
- Claude Code の Sonnet でだけ点を出しました。ほかのツール、ほかのモデルでは点を出していません。
- Skill を入れている人向け：自分の作業を終えたあとで「そのまま貼れる報告文を書いて」と頼まれる場面では、この文を足しても、報告文の書き方の Skill は読まれませんでした。文の中の「問いに当たる Skill が入っていれば、その節目で読む」も、試した範囲では効いていません。点を出したときの文と同じものを載せるために、残しています。
